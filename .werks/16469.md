# MTR agent bakery rule: allow IPv6 addresses as destination

key        | value
---------- | ---
date       | 2026-08-19T13:10:25+00:00
version    | 2.5.0p12
class      | fix
edition    | cee
component  | agents
level      | 1
compatible | yes

The agent bakery ruleset "MTR (Matt's traceroute) (Linux)" rejected any
*Destination address* containing a colon, so an IPv6 address could not be
configured - even though the same rule offers an "Enforce IPv4 / IPv6" option
and the agent plugin handles IPv6 destinations without problems.

Colons are now accepted. The character is not part of the characters Checkmk
forbids in service descriptions, so it can safely be used.

IPv6 zone identifiers (for example `fe80::1%eth0`) remain unsupported: the
Nagios core strips `%` from service descriptions, which would make the service
description differ from the discovered item.
