# BI aggregations rule: accept aggregation groups unknown to the local site

key        | value
---------- | ---
date       | 2026-10-02T09:41:53+00:00
version    | 2.4.0p39
class      | fix
edition    | cre
component  | bi
level      | 1
compatible | yes

Updating a site to 2.5.0 could abort during the ruleset validation of
`cmk-update-config` with an error like:

_Ruleset: special_agents:bi ... Exception: Validation errors: [ValidationMessage(location=['options', '0', 'filter', 'aggr_group_prefix', '0'], message="Invalid choice 'MY_GROUP'", ...)]_

The option _By aggregation group prefix_ of the _BI aggregations_ rule only
accepted the aggregation groups known to the local site. Rules are not
filtered per site, so they may refer to groups which don't exist locally,
e.g. groups of a deleted aggregation, of a different site or, on remote
sites of the multi-tenancy edition, of a different customer. Such rules
were rejected. On appliances the update was rolled back, since there is no
way to continue despite the warning.

The group prefix is now a text field which suggests the known aggregation
groups but accepts any group name. Existing rules don't need to be changed.
