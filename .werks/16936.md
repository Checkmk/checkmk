# BI now rejects invalid regular expressions

key        | value
---------- | ---
date       | 2026-10-02T15:12:21.735352+00:00
version    | 2.4.0p38
class      | fix
edition    | cre
component  | bi
level      | 1
compatible | no

The regular expression fields of BI rules and aggregations accepted any text.
An invalid pattern like `?.(Instance001)?.` was saved without a warning. The
search preview then only said "Can not evaluate search", and the affected
nodes silently stayed empty.

This affected the host name and host alias patterns, the service regex of a
service search and the host and service fields of "State of a host" and
"State of a service" nodes.

Saving a BI rule or aggregation with an invalid regular expression is now
refused with an error message. The search preview shows the actual
regular expression error. The help texts of these fields now also explain
whether the pattern has to match the beginning or the whole name.

Invalid patterns that are already stored are left untouched, so the
affected nodes stay empty after the update, as they did before. To find them,
check the output of the update (`cmk-update-config`) for lines like:

```
BI pack 'my_pack', rule 'my_rule': invalid regular expression '*.*foo' in
'service_regex' (nothing to repeat at position 0). ...
```

Fix each reported pattern in *Setup > Business Intelligence*. Until then,
saving the affected rule or aggregation is refused.
