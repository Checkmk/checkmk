# Time-specific toggle discards rule input

key        | value
---------- | ---
date       | 2026-10-20T13:30:33+00:00
version    | 2.4.0p38
class      | fix
edition    | cre
component  | wato
level      | 1
compatible | yes

When editing a rule, clicking *Enable timespecific parameters* or
*Disable timespecific parameters* reloaded the page instead of just
switching the mode. All values entered so far were lost, and
*Default parameters when no time period matches* showed the stored or
default values again.

The button now only switches between the plain and the time-specific
parameters and keeps your input. This affected all rulesets offering
time-specific parameters, e.g. *Check Point VSID packet rate*.
