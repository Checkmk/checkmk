# Agent Controller auto-registration: Baking failed for a trusted remote site

Previously, baking agents with an _Agent Controller auto-registration_ rule that registers to a remote site could fail with

```
Could not load certificate for site '<site ID>'
```

even though the CA of the remote site was listed under _Trusted certificate authorities for SSL_ and the Livestatus connection to that site worked fine.

The bakery takes the CA of a remote site from a store that Checkmk fills whenever you save that global setting in the GUI or via the REST API. If the setting reached the central site in another way, for example by copying configuration files or restoring a backup without the `var` directory, the store stays empty and the bakery has nothing to put into the agent package.

You can now repair this from the GUI: open _Setup > Distributed monitoring_, go to the _Livestatus encryption_ page of the remote site and click _Add to trusted CAs_ on the CA entry of the certificate chain. Checkmk still tells you that the CA is already trusted, but it also refreshes the store, so the next bake succeeds.
