# Faster effective parameters page and search for ineffective rules

In setups with many rules, some pages in the Setup took very long to load
or even ran into a timeout. This affected in particular:

- The page _Effective parameters of_ a host
- The _Ineffective rules_ page and rule searches using the _Ineffective rules_ option
- The rule list of a ruleset when opened for a specific host

To find out which rules match a host, Checkmk asked the monitoring core
configuration once per ruleset. Every one of these requests has to load the
complete configuration of the site, so the loading time grew with the number
of rulesets shown on the page.

These pages now collect the result for all rulesets with a single request.
The matching itself is also cheaper: when rules are matched against a single
host, their conditions are evaluated directly for that host instead of
preparing the matching for all hosts of the site first.

The displayed results do not change, with one exception: The search for
ineffective rules now also takes hosts into account that are excluded from
the monitoring, which usually are the hosts with the tag _offline_.
A rule that only matches such hosts is still in use and is no longer shown
as ineffective.
