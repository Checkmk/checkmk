# Eaton UPS: fix "enviroment" typo

The check plug-in for the temperature and humidity sensors of Eaton UPS devices,
its SNMP section, its rule set and its service were misspelled as
<tt>enviroment</tt>. The check plug-in and the SNMP section have been renamed to
<tt>ups_eaton_environment</tt>, and the rule set <i>Temperature and Humidity for
Eaton UPS</i> to <tt>eaton_environment</tt>. New sites use the corrected
service name <tt>Environment</tt>, on existing sites it is available as an
option.

The update migrates the existing configuration automatically:

- Discovered services are moved to the renamed check plug-in, so no rediscovery
  is required.
- Rules of the rule sets <i>Temperature and Humidity for Eaton UPS</i> and
  <i>Enforced services</i> are moved to the renamed rule set, and enforced
  services as well as <i>Disabled checks</i> rules refer to the renamed check
  plug-in.
- Rules of the rule sets <i>Disabled or enabled sections (SNMP)</i>,
  <i>Fetch intervals for SNMP sections</i> and <i>SNMPv3 contexts to use in
  requests</i> refer to the renamed SNMP section.
- Notification rules, including personal ones, and alert handler rules that
  match on the check plug-in (<i>Match check types</i>) refer to the renamed
  check plug-in.

On existing sites, the service keeps its name <tt>Enviroment</tt>, so the
recorded metric history is preserved.

To switch an existing site to the corrected service name <tt>Environment</tt>,
enable <i>Eaton UPS: Temperature and humidity sensors</i> under
<i>Setup > General > Global settings > Execution of checks > Use new service
names</i>. Note that the metric history recorded under the previous name
<tt>Enviroment</tt> is not carried over to the new service name.

This change is incompatible if you refer to the check plug-in or SNMP section
name <tt>ups_eaton_enviroment</tt> or the rule set name <tt>eaton_enviroment</tt>
in places the update does not migrate. Please adjust them to the new names:

- Views and dashboards filtering on the check command
  <tt>check_mk-ups_eaton_enviroment</tt>.
- Scripts using the REST API or Livestatus, and command lines such as
  <tt>cmk --checks=ups_eaton_enviroment</tt>.
