# IBM MQ: Fallback service state ignored without state mapping

key        | value
---------- | ---
date       | 2026-10-07T09:50:34.085330+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

The rule sets _IBM MQ channels_ and _IBM MQ managers_ offer the option _Service state if no map rule matches_.
Previously, this option was silently ignored unless the parameters of the service also contained a state mapping.
Channel and manager states the check doesn't know were then always reported as `UNKN`.

The option now also applies to states the check doesn't know if no state mapping is configured.
