# Fix wrong reports of invalid DCD configurations during site update

key        | value
---------- | ---
date       | 2026-09-29T15:30:00.000000+00:00
version    | 2.5.0p16
class      | fix
edition    | pro
component  | dcd
level      | 1
compatible | yes

This affects sites that have the global setting *Hide folders without read
permissions* enabled.

During `omd update`, the dynamic host configuration was verified with no user
logged in. The folder choice of a creation rule is filtered by the folder read
permission, and a user that is not logged in sees only the main folder. For
every connection whose creation rule places hosts in a folder below the main
folder, the update therefore reported

```
Invalid configuration for dynamic host config connector '<name>':
  Invalid choice '<folder/path>' (location: ['creation_rules', '0', 'create_folder_path'])
```

and asked whether to continue, although the same rule opened without error in
Setup. Answering `c` was safe: the verification only reads the configuration.

Starting with this release, the verification runs with the same permissions as
the update itself, so these false errors no longer appear.
