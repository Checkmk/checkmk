# mk-sql: no login attempts for inaccessible databases

When monitoring Microsoft SQL Server, the agent opened a login on every
database to collect the per-database sections. If the monitoring login could
not open a database, because the database was offline, restoring or access was
not granted, every one of these attempts failed and filled the SQL Server error
log with 18456 and 4060 messages.

Starting with this release, the agent determines up front which databases it
can access and logs in to those only. Databases it cannot access are reported
with an error line in the agent output, as the legacy `mssql.vbs` plugin did.
This affects the per-database sections `clusters`, `transactionlogs`,
`tablespaces` and `datafiles`; the `clusters` section is affected on clustered
instances only.
