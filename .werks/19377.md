# Analyze configuration: Report GUI plug-ins by their actual effect

The "GUI plug-ins" and "Legacy GUI plug-ins" tests in "Analyze configuration" said of every Python file below `local/lib/python3/cmk/gui/plugins` and `local/share/check_mk/web`
that it uses a deprecated API. They did not look at where the file is, and most of these plug-ins have no supported API to migrate to. The "Legacy GUI plug-ins"
test also skipped files in folders named metrics, perfometer and wato silently.

The tests now report each file by its folder:

- A file in a folder that Checkmk loads is WARN. It uses internal interfaces of Checkmk that are not supported for plug-ins and may break with any update.
- A file in a metrics or perf-o-meter folder is CRIT. Checkmk no longer reads graphs, metrics and perf-o-meters from these folders. Re-implement it with the supported API
  cmk.graphing.v1.
- A file in any other folder is CRIT. Checkmk does not load it, so it has no effect.

Broken GUI extensions, which Checkmk fails to load, are no longer reported as using an outdated API. Their finding says that they have no effect, gives the error and
refers to `var/log/web.log`.

PNP templates in `local/share/check_mk/pnp-templates` are no longer called deprecated. Checkmk no longer reads them, so they are CRIT with the hint to
re-implement them with cmk.graphing.v1.

The test for HW/SW inventory display hints now also looks in `local/lib/python3/cmk/gui/plugins/views`, where they work as well.

The daily deprecation messages use the same texts. An extension package with such plug-ins gets a message of its own, which describes the package as a whole.
WARN is now shown in a warning box instead of a red error box, and the states of several findings no longer overlap.

The messages about deprecated and about unknown check parameter rule sets now say what happens to the rules and what to do about them.
