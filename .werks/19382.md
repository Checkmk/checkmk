# HW/SW Inventory: Inventory trees saved by earlier versions with table retention intervals could not be converted

class      | fix
edition    | community
component  | inv
level      | 1
compatible | yes

This is a follow-up to werk #19381.

Inventory trees saved by Checkmk 2.4.0 or earlier use a Python format. If a rule
*Retention intervals for HW/SW inventory* kept columns of a table, these trees
contain retention intervals keyed by the values of the row's key columns. JSON
cannot store such keys. Writing such a tree as JSON failed with:

TypeError: keys must be str, int, float, bool or None, not tuple

This happened in the following situations:

* The service *Check_MK HW/SW Inventory* moved such a tree to the history of
  the host.
* A central site stored such a tree fetched from a remote site.
* The nightly conversion of inventory trees to JSON
  (`cmk-transform-inventory-trees`) processed such a tree. Since the
  conversion took up the same batch of trees again every night, it stopped
  converting trees of the site for good.

Inventory trees saved by earlier versions are now converted to the new format
of the retention intervals before they are written as JSON.

Furthermore, a tree that cannot be converted no longer stops the nightly
conversion. The error is logged and the conversion goes on with the next tree.
