# HW/SW Inventory: Update warns about trees in the legacy file format

key        | value
---------- | ---
date       | 2026-11-25T13:03:04+00:00
class      | feature
edition    | community
component  | inv
level      | 1
compatible | yes

Since Checkmk 2.5.0, HW/SW Inventory trees are stored as JSON. A nightly
cron job converts the trees that still use the previous file format,
1/200 of all trees per run. Checkmk 3.0 reads only trees in the new file
format, so all trees must be converted before updating to it.

The pre-update checks of `cmk-update-config` now warn while trees in the
legacy file format are left. The warning shows how many trees are left and,
once the nightly job has converted some trees, an estimate of how long
converting the rest takes. The update itself continues. Updates from
Checkmk 2.4 or earlier skip this check: these versions neither convert trees
nor provide the conversion command.

To convert the remaining trees right away, for example outside business
hours, run as site user:

```
cmk-transform-inventory-trees --bundle-length <number of trees left>
```

To see the progress and the trees of hosts that no longer exist, run:

```
cmk-transform-inventory-trees --show-results
```

Trees of hosts that no longer exist are never converted. Delete the files
listed under "Legacy trees of removed hosts" before updating to Checkmk 3.0.
Previously, this list was called "Unknown file paths" and showed tree files
that existing hosts did not have, but not the trees of removed hosts.

The nightly job now writes its errors to
`var/log/inventory-transformation.log`. Previously, they were lost unless an
admin email address was configured for the site. If the host list cannot be
retrieved, the job now stops with an error instead of running with no hosts.
