# Relay hosts: rescheduled active checks no longer time out too early

key        | value
---------- | ---
date       | 2026-10-16T10:12:53.282444+00:00
version    | 2.5.0p18
class      | fix
edition    | ultimate
component  | relay
level      | 1
compatible | yes

When you rescheduled an active check of a host monitored through a relay, the core
counted the check timeout from the moment it handed the check to the relay. The relay,
however, starts the check only when it picks it up. This had two effects:

- A check that finished on the relay within its timeout could still end as `UNKN`
  with "(Check timed out after 60 seconds)" when the relay picked it up late.
- When the relay did not answer at all, for example because it was offline, the
  service showed the same timeout message instead of the actual reason.

The core now waits 15 seconds longer than the configured check timeout for these
checks. The relay still stops the check command after the configured timeout. When
the relay does not answer, the service now shows `UNKN` with "relay execution
failed" and the reason.

Checks that the relay schedules on its own are not affected.
