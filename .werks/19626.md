# winperf_phydisk: stale Disk IO services on busy Windows disks

key        | value
---------- | ---
date       | 2026-11-17T10:00:00+00:00
class      | fix
edition    | community
component  | checks
level      | 2
compatible | yes

The `Disk IO` services of Windows hosts went stale at irregular intervals,
although the agent delivered complete data for the affected disk.

Windows keeps the counters behind `Avg. Disk sec/Read` and `Avg. Disk sec/Write`
in 32 bits. They count the summed wait time of all IO operations and restart at
zero once they reach their limit, which a busy disk does within minutes. The
check treated the decreasing value as unusable and discarded the whole disk,
including throughput, IO operations and queue length. Disks under load restarted
these counters most often, so the values that matter most were missing most
often.

Starting with this release, the check reads the summed wait time from the
counters behind `Avg. Disk Read Queue Length` and `Avg. Disk Write Queue
Length`. Windows keeps those in 64 bits and counts the same sum in them, so they
do not restart. The remaining 32 bit counters count operations. Those restart at
most once between two checks, and the check corrects that. A counter reset, for
example after a reboot of the monitored host, is still recognized as such and
skipped for one check interval.

Hosts that report no performance frequency now deliver the two latency values as
well. The queue length counters count in fixed units of 100 nanoseconds and need
no frequency.

The two counters the latency is computed from start from an empty state after
the update. The `Disk IO` services of Windows hosts therefore deliver no values
for one check interval and keep their previous state; from the next interval on
they report as usual.
