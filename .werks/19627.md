# winperf_phydisk: swap read and write latency

key        | value
---------- | ---
date       | 2026-11-17T10:30:00+00:00
version    | 2.4.0p43
class      | fix
edition    | cre
component  | checks
level      | 2
compatible | no

The `Disk IO` services of Windows hosts published the read and the write
latency under the name of the opposite direction. `Average read wait` showed
the write latency, and `Average write wait` showed the read latency. Both
values themselves were correct, and the summary value `Latency` is the larger
of the two and was therefore not affected.

This is a regression introduced in Checkmk 2.0.0 by
[Werk #11224](https://checkmk.com/werk/11224), which migrated the check plugin
to the new check API. Checkmk 1.6.0 and earlier were not affected.

Starting with this release, both values are published under the name of their
own direction.

The meaning of the metrics `Average read wait` and `Average write wait` changes
for Windows hosts. Review the levels configured for them in the ruleset "Levels
on disk IO", and expect the recorded history of these two metrics to be swapped
relative to the data recorded from now on.
