# Hosts of a dynamic host management connection can be edited again

key        | value
---------- | ---
date       | 2026-11-18T14:39:17+00:00
class      | fix
edition    | pro
component  | dcd
level      | 1
compatible | yes


Checkmk 2.5.0p6 began to validate the IDs of dynamic host management
connections, and werk #19229 removed that validation again. A second, older
restriction remained in place: every host such a connection creates carries
the connection ID in its *Locked by* attribute, and that attribute declared
the ID to be an identifier.

Saving such a host in Setup therefore failed with *An identifier must only
consist of letters, digits, dash and underscore and it must start with a
letter or underscore*, even when nothing had been changed. The attribute is
read only, but it is submitted together with the form and validated with it,
so the error could not be avoided. Every host of a connection whose ID
contains a character outside that set, a dot for example, was affected.

The connection ID is now accepted as free text in that attribute, as the REST
API has always accepted it. Affected hosts can be edited again. No
configuration change is required.
