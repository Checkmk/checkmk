# Agent bakery: handle failed builds correctly

key        | value
---------- | ---
date       | 2026-11-23T16:30:08.358754+00:00
class      | fix
edition    | pro
component  | agents
level      | 1
compatible | yes

When the agent bakery could not build a package, the failure was not reported
reliably, and a later bake could put a damaged package into circulation. One
way to run into this was a custom file larger than the 64 MiB that the Windows
agent package format allows per file.

Three problems occurred:

* *Bake and sign agents* ended in an internal error with a crash report. The
  bakery tried to sign the package that the failed build had never written, so
  the report showed a `FileNotFoundError` instead of the reason the build
  failed. *Bake agents* named the reason, but also ended in an internal error
  with a crash report instead of a failed job.

* After acknowledging the failed bake, a second bake reported success and
  offered the package for deployment. The files of the aborted build were kept
  and reused, so the package was assembled from an incomplete file set. For
  Windows this produced an agent package without any baked plug-ins and without
  the configured custom files, and nothing reported a problem.

* The failed bake also took the working package away from the affected hosts.
  Their reference was moved to the package the build had never written, so the
  agent download and the agent updater found nothing for that platform. When
  baking for all hosts, the previous package was deleted from the site on top
  of that.

Starting with this release, a package that cannot be built is rejected:

* The build failure is reported as a bake problem. The baking job ends as
  failed and shows which hosts are affected and why, for *Bake agents* and for
  *Bake and sign agents* alike. No internal error and no crash report are
  created, and a package that failed to build is no longer signed.

* The files of an aborted build are discarded. The next bake assembles the
  package from scratch and fails again with the same message, so an incomplete
  package can no longer reach the agent deployment.

* A platform whose build failed keeps the reference it had, and its package is
  no longer deleted. The affected hosts stay on the agent package they had
  until the cause is fixed, the same way as after a failing bakery plug-in.
