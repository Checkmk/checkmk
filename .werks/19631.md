# Windows agent: switch off a single winperf counter

key        | value
---------- | ---
date       | 2026-11-25T10:57:57.248799+00:00
class      | feature
edition    | community
component  | checks
level      | 1
compatible | yes

The counters of the `winperf` section could only be added, never removed. The
Windows agent merges the counter list of `check_mk.yml`, of the file written by
the agent bakery and of `check_mk.user.yml` instead of overriding it, so a
counter that one file added stayed in the configuration whatever a later file
said. The example in `check_mk.user.yml` offered `- 234: -` for this purpose.
That is not valid YAML, and it stopped the whole file from being read.

Starting with this release, the value `$DISABLE` removes a counter:

```yaml
winperf:
    counters:
        - 234: $DISABLE
```

The counter with that id, or with that name, is not monitored. The files are
read in the order `check_mk.yml`, the file of the agent bakery,
`check_mk.user.yml`, and the last file that names the counter decides. A file
read after the marker can therefore switch the counter on again, by giving its
id a name. `check_mk_agent.exe showconfig winperf` lists the entry with the
`$DISABLE` value in place of the counter, so a switched off counter stays
visible. The marker works in every agent configuration file.
