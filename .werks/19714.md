# Fix crash of AKCP checks on undocumented sensor status "0"

key        | value
---------- | ---
date       | 2026-07-20T17:03:13.118547+00:00
version    | 2.4.0p36
class      | fix
edition    | cre
component  | checks
level      | 1
compatible | yes

Previously, the AKCP _Dry Contact_, _Water_, _Smoke_, _Humidity_, and
_Temperature_ services could crash with an error like `KeyError '0'`.

Some AKCP devices report a sensor status of `0`, a value not defined in
AKCP's own MIB, both while online and while offline. This has been fixed:
the affected service now goes stale for that check instead of crashing.
