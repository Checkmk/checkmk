# "Do not match Event Console alerts" matched only Event Console alerts

---------- | ---
date       | 2026-08-10T14:13:35.742418+00:00
version    | 2.5.0p13
class      | fix
edition    | community
component  | notifications
level      | 2
compatible | no

Notification rules configured to not match Event Console alerts did the exact
opposite: they matched Event Console alerts only, and stopped matching host and
service notifications.

This is a regression introduced in Checkmk 2.4.0p10 by
[Werk #18082](https://checkmk.com/werk/18082), which reworked Event Console
alert matching without covering this option. Matching is now correct again: such
rules exclude Event Console alerts and match host and service notifications as
configured by their other conditions.

Affected are rules created before Checkmk 2.4, rules for users and personal
notification rules, and rules created via the REST API with
`conditions.event_console_alerts.value.match_type` set to
`do_not_match_event_console_alerts`.

Such a rule also no longer opens in the notification Quick Setup with an empty
"Specific events" selection that could not be saved. It now shows all host and
service events with "Event Console alerts" unselected, which is equivalent.
Note that saving the rule there stores that explicit event selection, so the
REST API reports `event_console_alerts` as disabled afterwards.

Please review notification rules that use this option, since this change may
affect your notification behavior.
