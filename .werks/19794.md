# REST API: more lists name unreachable sites

key        | value
---------- | ---
date       | 2026-11-19T08:45:15.008201+00:00
version    | 2.5.0p22
class      | fix
edition    | community
component  | rest-api
level      | 1
compatible | yes

In a distributed setup, when a remote site could not be reached, six more
lists of the REST API left out that site's objects without any notice: the
lists of comments, of downtimes, of current and of historical Event Console
events, and of host and of service availability. A script or tool reading
these lists couldn't tell that data was missing.

These lists now name the sites that could not be reached under
`extensions.unreachable_sites`, as the lists of hosts and services do since
[Werk #23014](https://checkmk.com/werk/23014). The field is always present and
is an empty list when every site answered.

The same lists also carry `extensions.incomplete`. It is `true` when at least
one site could not be reached, so a script can check one flag.
