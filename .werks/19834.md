# Linux memory: new graphs for newer kernel fields and fixed graph totals

version    | 3.0.0b1
class      | feature

level      | 2
compatible | yes

The _Memory_ service of Linux hosts has new graphs for memory fields that
newer kernels report: _Slab_, _Misc memory types_, _Contiguous memory
allocator_, _Zswap_, _RAM used by GPU drivers_ and _VM guest memory_. The GPU
graph shows system memory that GPU drivers hold, not the graphics card's own
memory. Metrics that showed up as separate single-metric graphs are now part
of these or of existing graphs.

Three graphs showed wrong totals and are fixed:

- _Swap_: swap cached is part of swap used and is no longer stacked on top of
  it.
- _Caches_: only reclaimable slab counts as cache, matching the cache total
  Checkmk subtracts from used RAM.
- _Memory committing_: the commit limit is a line, no longer stacked on top of
  the committed memory.

Bounce buffers are no longer part of _Disk Writeback_ and its graph. They are
block layer copies, not data waiting to be written, and kernels since 6.16
always report them as zero. They are now shown in _Misc memory types_.

MemAvailable is now called "Available RAM (kernel estimate)" in its graph, in
the ruleset _Memory levels for Linux_ and in the service output. If you are
using rules which match on service output for "RAM available", please adapt
these rules.
