# Relay hosts: show the check result instead of a relay client log line

key        | value
---------- | ---
date       | 2026-10-12T14:59:12.130484+00:00
version    | 2.5.0p16
class      | fix
edition    | ultimate
component  | relay
level      | 1
compatible | yes

On a host monitored through a relay, the service _Check_MK HW/SW Inventory_ and rescheduled active checks could show a relay client log line as their summary instead of their result, for example:

`Relay client: Response: [403]: {"detail":"The maximum number of tasks 10 has been reached"}`

This happened when the site's request to the relay failed, for example when the agent receiver answered with an error or a task expired before the relay picked it up. Rescheduled active checks also showed connection retry messages, for example while the agent receiver was restarting. The actual result was moved to the service details; the service state was always correct.

The summary now shows the check's own result again.
