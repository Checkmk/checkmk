# Redact SNMP community, SNMPv3 pass phrases, and IPMI password in host config REST API GET responses

key        | value
---------- | ---
date       | 2026-05-27T13:34:42.713394+00:00
version    | 2.5.0p15
class      | security
edition    | community
component  | rest-api
level      | 1
compatible | no

GET requests to the host and folder configuration endpoints of the REST API returned stored secrets in clear text:

 * `snmp_community` -- the SNMP v1/v2 community string and the SNMPv3
   `auth_password` and `privacy_password` pass phrases
 * `management_snmp_community` -- the same fields for the management board
 * `management_ipmi_credentials` -- the IPMI `password`

The setup GUI never shows these values, not even to an administrator. The REST
API did not follow that principle, so any user permitted to view a host's
configuration could read them back -- an account with the built-in "user" role
that is a contact for the host is sufficient.

These fields are now omitted from GET responses. The surrounding non-secret
fields (`type`, `auth_protocol`, `security_name`, `privacy_protocol`, IPMI
`username`, ...) are still returned, so clients can still tell which kind of
credential is configured. The fields remain mandatory when creating or updating
a host, which is why this werk is incompatible: a client that reads a host's
configuration and sends it back unchanged now receives "Missing SNMPv3 pass
phrase(s)" and must supply the credentials explicitly.


### Affected Checkmk Versions

* 2.5.0
* 2.4.0
* 2.3.0
* 2.2.0 (EOL)
