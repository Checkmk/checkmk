# Bearer token authentication no longer starts a GUI session

key        | value
---------- | ---
date       | 2026-08-14T06:54:59.851751+00:00
version    | 2.5.0p13
class      | fix
edition    | community
component  | multisite
level      | 1
compatible | yes

Requests to GUI pages, for example `login.py` or `index.py`, that authenticated with an
`Authorization: Bearer <user> <password>` header were treated like an interactive login:
Checkmk stored a user session for them and answered with a session cookie.

Requests authenticated by a Bearer header no longer store a session and no longer receive a
session cookie. Each request is authenticated from the header alone, as was already the case
for the REST API.

This is not a security fix. The caller had to present valid credentials, and the session
cookie granted no access beyond what those credentials already granted.
