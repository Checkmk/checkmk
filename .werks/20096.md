# REST API: metrics association now uses a single list of host name lookup rules

key        | value
---------- | ---
date       | 2026-07-10T08:18:01.665771+00:00
version    | 3.0.0b1
class      | feature
edition    | ultimate
component  | rest-api
level      | 1
compatible | no

When creating, updating or reading a host or a folder via the REST API, the "OpenTelemetry data" attribute (`metrics_association`) has changed its shape.

Previously the enabled configuration held a required `attribute_filters` object and a required `host_name_resource_attribute_key`.

It now holds a single required `host_name_lookup_rules` list.
Each entry describes one set of filters with its `resource_attributes`, `scope_attributes` and `data_point_attributes`.
A host has at least one entry, so the list must not be empty.
The host name key is gone: the OpenTelemetry data of a host is selected by its filters only, never by matching the host name.

To migrate, move your `attribute_filters` into a single entry of the new list.
To keep selecting the same data, add the filter `<key> = <host name>` to its `resource_attributes`.
The update does this for hosts created by a telemetry metrics dynamic host management connection.
On all other hosts, on folders and in piggyback creation rules, the update disables the attribute; configure filters there to receive data again.

Before:
```
["enabled", {
    "attribute_filters": {
        "resource_attributes": [{"key": "team", "value": "shop"}],
        "scope_attributes": [],
        "data_point_attributes": []
    },
    "host_name_resource_attribute_key": "service.name"
}]
```

After, for a host named `checkout`:
```
["enabled", {
    "host_name_lookup_rules": [
        {
            "resource_attributes": [
                {"key": "team", "value": "shop"},
                {"key": "service.name", "value": "checkout"}
            ],
            "scope_attributes": [],
            "data_point_attributes": []
        }
    ]
}]
```
