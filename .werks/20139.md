# Crash reports view with broken traceback

Previously, opening _Monitor_ > _System_ > _Crash reports_ could fail entirely
with:

_Internal error: too many values to unpack (expected 4)_

This happened when a single stored crash report contained a traceback Checkmk
could not interpret, for example one recorded as plain text rather than as
individual code locations. One such report made the whole list inaccessible.

The list now renders. Reports with an uninterpretable traceback are still shown;
only their _Crash source_ column can no longer tell whether an extension was
involved. No currently supported Checkmk version writes reports like this, so
this is a safeguard for reports left behind by other producers.
