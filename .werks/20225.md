# Host rename: Move the piggyback data a renamed host delivers

Renaming a host that delivers piggyback data for other hosts left that data behind under the old host name.
Its piggybacked hosts were then fed under both names until the data of the old name exceeded the *Maximum age for piggyback files*.
Until then, services could show duplicated items or outdated values, and the service discovery did not report the services of the old name as vanished.

This also affected distributed setups with the piggyback hub enabled.
The rename only runs on the site that monitors the renamed host, so the other sites kept their copies of the data under the old name.

The rename now moves this data on the site of the renamed host.
The piggyback hub forwards the data under the new name right away.
It now also forwards that the data under the old name was moved away, so the other sites delete their piggyback data under the old name.
In the following cases, a site keeps the data of the old name until it exceeds the maximum age, as before:

* The site cannot be reached for more than a minute.
* The piggyback hub of the site does not process the removal within 10 minutes.
* The piggyback hub of the renamed host's site is stopped or has lost its connection to the message broker.
* The piggyback hub of the renamed host's site falls behind during the rename. This can happen when a source of many piggybacked hosts is renamed.
* The site still runs an older version, for example during an update.

In addition, the summary of the rename job listed the moved piggyback data one character per line.
This has been fixed as well.

Data left behind by an earlier rename is not moved, but the regular cleanup removes it.
