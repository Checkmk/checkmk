# Availability: apply all group filters when grouping

key        | value
---------- | ---
date       | 2026-08-25T06:58:55.490434+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | multisite
level      | 1
compatible | yes

Grouping an availability view by host groups or service groups ignored part of
your filters.

Combining two group filters could silently drop one of them: with _Several
service groups_ set to a selection and _Service is in Group_ negated (the host
variants behave the same), the selection was ignored altogether, so groups you
never selected still got their own rows in the availability table.

Grouping by host groups was affected even without any filter at all. The builtin
service views carry an empty _Host is in group_ filter in their context, which was
enough to remove every host group, leaving all rows under _Not contained in any
group_.

Both group filters are now applied to the grouping, in any combination of
positive and negated. As a side effect, the group restriction is no longer
reimplemented inside the availability computation - it now asks the very filters
that built the Livestatus query, so the fetched rows and the grouping can no
longer disagree.
