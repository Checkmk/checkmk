# Windows agent: Python module updated to 3.13.18

key        | value

date       | 2026-11-24T18:32:30+00:00
class      | fix
edition    | pro
component  | agents
level      | 1

The Python module of the Windows agent (python-3.cab, installed with the
"Install Python runtime environment" bakery rule) now contains Python 3.13.18.
It contained 3.13.17 before.

Python 3.13.18 is a security release; see its
[release notes](https://www.python.org/downloads/release/python-31318/) for
the fixed issues. None of these flaws affect Checkmk directly. Updating the
runtime reduces the scope of an attack against the agent.

python.org no longer publishes Windows builds of Python 3.13, which is in its
source-only security phase. The interpreter therefore now comes from
[python-build-standalone](https://github.com/astral-sh/python-build-standalone),
which builds CPython with the same Microsoft compiler and optimizations as
python.org. The packages in the module's virtual environment and the bundled
OpenSSL (3.5.9) are unchanged. What changes:

- The interpreter's files (`python.exe`, `pythonw.exe`, the Python DLLs and
  the `.pyd` modules) are no longer signed by the Python Software Foundation.
  If you allow programs on your Windows hosts by publisher, for example with
  AppLocker, Windows Defender Application Control or an EDR policy, allow
  `C:\ProgramData\checkmk\agent\modules\python-3` by path or file hash
  instead. Otherwise the agent's Python plug-ins and the agent updater stop
  running.
- The module no longer brings its own copy of the Universal C Runtime (UCRT).
  It uses the one that is part of Windows 10 and Windows Server 2016 and
  later, which covers every Windows version the agent supports.
- The OpenSSL DLLs are now called `libcrypto-3-x64.dll` and
  `libssl-3-x64.dll` (before: `libcrypto-3.dll` and `libssl-3.dll`). This
  only matters if you refer to them by name, for example in the allow list of
  a vulnerability scanner.
- The module now contains Python's license, `LICENSE.txt`.
