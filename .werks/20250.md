# Cisco Meraki: handle unmapped device status

key        | value
---------- | ---
date       | 2026-07-31T10:42:19.171279+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

The "Device Status" service for Cisco Meraki devices could crash with a
`KeyError` if the device reported a status value that the configured "Map
device status to monitoring state" rule did not cover (for example, a rule
saved before all four status values became mandatory in the rule editor).

The check now falls back to the plugin's built-in default monitoring state
for that status instead of crashing, and only shows UNKNOWN if the status
is not one of the four known device statuses at all.
