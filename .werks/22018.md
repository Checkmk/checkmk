# Management boards and their rules can no longer be added

version    | 3.0.0b1
class      | feature
edition    | community

compatible | no

Configuring management boards in the host properties is deprecated and will be removed in Checkmk 3.1.
Monitor a management board as a host of its own instead, using the IPMI special agent or SNMP.

From now on, you cannot add a management board to a host or folder anymore.
A cloned host does not take over the management board of its source.
The settings in the section "Management board" can only be changed, completed or removed on hosts and folders that already have at least one of them set explicitly.
An explicit "No management board" is kept, but does not count as such a setting.
Values a host inherits from its folder still apply.
In the GUI, you can no longer switch off an inherited management board for a single host. Use the REST API for this, as described below.

This affects the REST API as well:
Creating or updating hosts and folders is now refused with status 400 if it sets a management board attribute (`management_protocol`, `management_address`, `management_snmp_community` or `management_ipmi_credentials`) on an object that has none of them set yet.
Changing, completing or removing an existing management board still works.
Setting `management_protocol` to `none`, for example to switch off a management board inherited from the folder, is still accepted.
If you create hosts with a management board through scripts or other automation, change them to create a separate host for the management board.

The rule sets "Management board config" and "Enable SNMPv2c for management boards" are deprecated as well.
You now find them under "Deprecated rule sets" and cannot add new rules to them anymore.
Existing rules can still be edited and deleted.
