# Check_MK Discovery: do not crash on older periodic discovery rules

key        | value
---------- | ---
date       | 2026-08-06T14:08:54.700503+00:00
version    | 2.4.0p36
class      | fix
edition    | cre
component  | checks
level      | 1
compatible | yes

After upgrading, the "Check_MK Discovery" service of a host could go to UNKNOWN
with a crash report ("check failed - please submit a crash report!") showing the
exception `KeyError: 'update_changed_service_parameters'`.

This happened when a "Periodic service discovery" rule using a custom rediscovery
mode had been stored before the "Update service parameters" option was
introduced -- for example rules that were created via the REST API in an early
2.4 version and never re-saved afterwards.

The discovery check now tolerates these older rules by treating the missing
"Update service parameters" option as disabled, and no longer crashes.
