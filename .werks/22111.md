# Rittal CMC III: discover phase services when the sensor description is used

Previously, if the discovery ruleset _Rittal CMC III discovery_ was set to _Use
sensor description_, the phase services of a CMC III PDU were not discovered at
all. The _Check_MK Discovery_ service reported _check failed - please submit a
crash report!_ with `KeyError: 'DescName'`, and on the _Service discovery_ page
the already monitored phase services showed up as vanished without anything
replacing them. This has been fixed.

A word on the resulting service names, because they may look odd at first:
unlike the other CMC III sensors, a phase has no description of its own. The
device describes each of its measurements separately, for example "L1 Voltage",
"L1 Current" and "L1 Power". A phase service is therefore named after the first
of those measurements, so you will see a service like _Input 1-3 L1 Voltage_
that reports the voltage, current, power and energy of phase L1. If you prefer
different names, the ruleset _Translation of service descriptions_ can be used
to adjust them.

Sensors that report no description at all now keep the device and sensor name
as their item, for example _Temperature Ambient HUM_RA-01-E_. Some CMC III
sensor modules omit the description of their temperature channel, and those
sensors previously caused the same crash.
