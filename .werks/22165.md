# Check_MK Agent: Host name mismatch with agent updater no longer CRIT

key        | value
---------- | ---
date       | 2026-09-30T13:24:36.630467+00:00
version    | 3.0.0b1
class      | fix
edition    | pro
component  | checks
level      | 1
compatible | yes

Since [Werk #15358](https://checkmk.com/werk/15358), the service _Check_MK Agent_ has compared two host names.
The first is the host name under which the agent updater is registered.
The second is the name of the host in Checkmk.
A difference between the two sent the service to `CRIT`.

This comparison caused false alarms.
A host can be monitored by several sites, and each site may know the host under a different name.
The agent updater, however, is registered with one site only.
All other sites therefore reported a mismatch, although they have nothing to do with agent updates.

The ruleset _Checkmk agent installation auditing_ now has the option _State in case of host name mismatch with the agent updater_.
This option defaults to `WARN`.
Previously, a mismatch always resulted in `CRIT`.

On sites that monitor a host without serving its agent updates, set this option to `OK`.
The service then shows the mismatch only in its details, next to the host name used by the agent updater.
If you want the previous behavior back, set the option to `CRIT`.
