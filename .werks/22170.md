# A failing bakery plug-in no longer affects other hosts

version    | 3.0.0b1
class      | fix
edition    | pro
component  | agents
level      | 1
compatible | yes

A bakery plug-in that failed for one host caused two problems for all
other hosts. An agent file that a rule references, but that is missing
on the site, had the same effects.

The page _Windows, Linux, Solaris, AIX_ highlights the buttons
_Bake agents_ and _Bake and sign agents_ when agent packages need
baking. With a failing plug-in, the page could not determine this for
any host. The buttons then stayed unhighlighted, as if all agent
packages were up to date. Nothing on the page pointed to the failure.

The bake itself stopped at the failing host. Hosts that came later in
the bake got no new agent packages, although their configuration was
valid. This also hit the bakes of the global setting _Automatically
create monitoring agents_. Their errors only appear in
`~/var/log/web.log`.

Now the page highlights the buttons in these cases as well. A warning
above the agent list names the affected hosts and folders, together
with the error message. If several plug-ins fail for a host, the
warning names each of them. If the check on the page fails for another
reason, the page still highlights the buttons.

The bake creates the packages of all other hosts. It still ends with
an error that names the affected hosts, and these hosts keep their
previous agent package. Such a bake now also removes the packages of
hosts that no longer exist.
