# Linux agent: The agent controller logs to a file

On Linux, the agent controller `cmk-agent-ctl` now also writes its log
to a file. Until now, its messages only went to the journal of the
`cmk-agent-ctl-daemon` service.

The file is called `cmk-agent-ctl.log`. Its location depends on the
deployment:

* Single directory deployment: `runtime/log/controller` below the
  installation directory, by default
  `/opt/checkmk/agent/default/runtime/log/controller/cmk-agent-ctl.log`
* Classic deployment: the home directory of the agent user,
  `/var/lib/cmk-agent/cmk-agent-ctl.log`

Only the daemon writes to the file. When the file reaches 500 kB, the
daemon starts a new one and keeps the last five. The old files carry a
timestamp in their name, for example
`cmk-agent-ctl_r2026-11-10_14-30-00.log`. All other commands, such as
`register` or a manual `update`, print their messages to stderr only,
as before.

The file contains messages of level info and above. Each message starts
with a timestamp, its level and its source. The options `-v` and `-vv`
only change the output on stderr. Only the agent user can read the
file.

In root mode of the single directory deployment, the agent package now
gives the group of the agent user access to `runtime/log`. The
controller needs that access to reach `runtime/log/controller`. Agent
packages that contain the agent updater already did this.
