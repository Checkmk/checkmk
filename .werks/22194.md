# SNMP section rule sets: matching rules no longer shown as overridden

key        | value
---------- | ---
date       | 2026-10-22T14:51:39.408804+00:00
version    | 2.4.0p40
class      | fix
edition    | cre
component  | wato
level      | 1
compatible | yes

Previously, the rule sets _Disabled or enabled sections (SNMP)_, _Fetch
intervals for SNMP sections_ and _SNMPv3 contexts to use in requests_ showed
only the first matching rule as applying to a host. Every further matching rule
was marked with "This rule matches, but is overridden by a previous rule", and
the host's effective parameters listed only the first rule.

This did not reflect what Checkmk actually does: all matching rules of these
rule sets apply, and for each SNMP section the first rule that covers it
decides. A rule shown as overridden could therefore still disable a section or
change its fetch interval or SNMPv3 contexts. For example, a general rule
disabling a section still applied to a host even though a host-specific rule
above it was shown as the one in effect, simply because that rule did not list
the section.

The rule lists and effective parameters now show all matching rules as
applying, and the help of each rule set explains which rule wins for a section.

One case did not follow this rule: in _Fetch intervals for SNMP sections_, a
rule set to "Fetch data every time" did not override an interval that a lower
rule configured for the same section. It now does, so such sections are fetched
at every check from now on. Apart from that, how your SNMP hosts are monitored
does not change.

If a higher-priority rule should override a lower one for a particular section,
list that section in the higher rule explicitly, for example under _Enabled
sections_.
