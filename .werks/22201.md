# Reports: graph elements from older reports no longer crash the report

key        | value
---------- | ---
date       | 2026-09-14T08:04:41.709362+00:00
version    | 2.5.0p14
class      | fix
edition    | pro
component  | reporting
level      | 1
compatible | yes

Viewing a report whose graph element referred to a host and service could
replace the report with a crash report:

C+:
TypeError: string indices must be integers, not 'str'
C-:

Reports store the host and service a graph element refers to, and older
reports may store the names directly rather than as filter settings. The
description of the element could not be built from that older form.

The description is only built while reporting that an element failed to
render, so this replaced the message naming the real problem with a crash
report, and the underlying failure stayed hidden. Such reports now render
again, and an element that fails is reported with its description as
intended.
