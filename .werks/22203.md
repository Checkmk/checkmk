# Crash reports with non-UTF-8 agent output can be opened again

version    | 3.0.0b1
class      | fix
edition    | community

Opening a crash report whose agent output was not valid UTF-8 replaced the
crash report page with a second crash:

C+:
UnicodeEncodeError: 'utf-8' codec can't encode character ... surrogates not allowed
C-:

This affected agents sending output in another encoding, most often a
Windows agent reporting a host name or path containing a character outside
UTF-8.

Since the agent output is shown on the page used to investigate a crash,
the effect was that exactly those crashes could not be looked at. The
agent output is now displayed with the undecodable characters replaced,
so the report opens and the rest of the output is readable.
