# Systemd discovery rejects empty conditions again

---------- | ---
date       | 2026-11-17T17:36:05.095062+00:00
version    | 2.5.0p22
class      | fix
edition    | community
component  | checks

compatible | no

The discovery rule sets _Systemd single service discovery_ and _Systemd single
socket discovery_ now also refuse an entry with an empty pattern in _Restrict by
description_ or _Restrict by name_. As before, they refuse these conditions
without any entry and _Restrict by state_ without any state.

Existing rules with empty conditions keep working as before and are not changed
by the update. An empty list of conditions still means "no restriction", and an
empty pattern still matches the way it did. If you have such a rule, the
configuration check of `cmk-update-config` reports it as an invalid rule
configuration and asks whether to continue. Open the rule in Setup afterwards
and untick the empty condition or enter a pattern; the affected fields are
marked.

The systemd rule sets _Systemd single service discovery_, _Systemd single socket
discovery_, _Systemd single service_, _Systemd single socket_, _Systemd
services summary_ and _Systemd sockets summary_ now use the current rule set
API.
