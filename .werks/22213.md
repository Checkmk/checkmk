# Update: rejected rule values are not crashes

During an update, `cmk-update-config` reported a rule whose value was rejected
by validation as "Exception in ruleset implementation detected" for all rule
sets built on the current rule set API. It created a crash report and
recommended disabling the affected rule. Such a rule is an invalid
configuration, not a broken plug-in.

It is now reported as "Invalid rule configuration detected", together with the
advice to open the affected rules in the GUI and fix them. No crash report is
created for it anymore.

A rule value that does not match the structure of its rule set points to a
broken migration in Checkmk or in an extension package. It is still reported
as an exception in the rule set implementation with a crash report, now also
for rule sets not yet built on the current rule set API, where it was reported
as an invalid configuration before.
