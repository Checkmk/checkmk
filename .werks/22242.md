# Activating changes interrupted flexible recurring downtimes

edition    | pro

If a rule in _Recurring downtimes for hosts_ or _Recurring downtimes for
services_ set a _Flexible downtime_ duration that differed from its _Duration_,
every activation of changes and every restart of the core replaced the downtime
with a new one. A downtime that had already started was cancelled. If the host
or service still had a problem and the downtime period was still open, the new
downtime started right away and ran for the full flexible duration again, so it
lasted longer than configured. If the period had already ended, the host or
service left its downtime early, and notifications about its problem could go
out.

The core now keeps these downtimes across activations and restarts.
