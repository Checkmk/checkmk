# omd: Fix the system Apache configuration of sites with APACHE_MODE none

key        | value
---------- | ---
date       | 2026-10-28T10:43:46.683172+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | omd
level      | 1
compatible | no

For a site with `APACHE_MODE` set to `none`, `omd update-apache-config SITE`
deleted the site's file in the system Apache configuration
(`/omd/apache/SITE.conf`). omd treats a site without this file as disabled with
`omd disable`, so `omd start` then refused to start the site with "This site is
disabled.".

The other commands that register a site with the system Apache (`omd create`,
`omd cp`, `omd restore` and `omd enable`) ignored `APACHE_MODE none` and wrote a
full proxy configuration, so the system Apache forwarded requests to a site
Apache that does not run.

For `APACHE_MODE none`, these commands now write the file without a proxy
configuration. The site stays registered and can be started, and the system
Apache no longer proxies requests to it.

If a site with `APACHE_MODE none` is affected, run
`omd update-apache-config SITE` as root.
