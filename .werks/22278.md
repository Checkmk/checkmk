# Special agents: fix race condition when storing data between runs

key        | value
---------- | ---
date       | 2026-09-30T08:35:44.309254+00:00
version    | 2.5.0p15
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

Special agents and active checks that keep data between runs could read an empty or incomplete value when two runs for the same host overlapped (for example a service discovery during a regular check).
Depending on the plug-in, this caused a crash or a lost cache for:

- Amazon Web Services (AWS)
- Azure, Azure (deprecated)
- Bazel remote cache
- Check email, Check email delivery, Check IMAP/EWS/GraphApi mailboxes
- Cisco Meraki
- Gerrit
- Kubernetes
- Proxmox VE
- Redfish compatible management controller, Redfish compatible power equipment (PDU)
- VMware ESX via vSphere

This data is now written atomically, so a concurrent run sees either the old or the new content.
