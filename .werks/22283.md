# Special agents can report messages in the Check_MK service

Special agents can now report messages in the _Check_MK_ service of the host.
There are two kinds of messages:

* Warnings report problems that did not stop the special agent from producing data, for example a single endpoint the configured account is not allowed to access.
* Infos report things worth knowing that are no problem. They are always shown with the state `OK`.

By default, a reported warning makes the _Check_MK_ service go to `WARN`.
You can change this state in the rule _Status of the Checkmk services_, under _State if the data source reports warnings_.

While a warning is reported with a state other than `OK`, the automatic service discovery and bulk discovery skips the host, as the data is probably incomplete.
If a special agent reports a warning on every run, the automatic service discovery is skipped until the problem is resolved.
If you want to accept the warning, set its state to `OK`.
The warning is still shown in the _Check_MK_ service.
The HW/SW inventory is not affected: it still processes the data and shows the messages in its service.

Developers of special agents can report messages using the new class `AgentMessages` of the server-side programs API (`cmk.server_side_programs.v1`).
