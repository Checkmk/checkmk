# Fix missing authorization check when rescheduling checks

Users with the permission "Reschedule checks" could force immediate checks on hosts and services they are not a contact for.
They could not see the results of these checks.

The following endpoints did not check whether the user may see the target host or service:

* The AJAX endpoint behind the "Reschedule check" icon in views (all affected versions)
* The internal REST API endpoint for rescheduling host checks (2.5.0 only)

Checkmk now only reschedules checks on hosts and services the user may see.
The same check was added to other internal REST API endpoints for host and service commands that were not part of any released version.

This werk is incompatible: the "Reschedule check" icon now also requires the permission "Perform commands in views".
The built-in roles already grant it.
If a custom role grants "Reschedule checks" only, add "Perform commands in views" to keep the icon.

We thank Alfie Goh Li Heng for reporting this issue.

### Who is Affected

This issue affects all editions of Checkmk in the default configuration.
To exploit it, an attacker needs a user account with the "Normal monitoring user" role or any other role that can reschedule checks.

### Affected Checkmk Versions

* 2.5.0
* 2.4.0
* 2.3.0 (EOL)

### Vulnerability Management

We have rated the issue with a CVSS Score of 5.3 Medium (`CVSS:4.0/AV:N/AC:L/AT:N/PR:L/UI:N/VC:N/VI:L/VA:L/SC:N/SI:N/SA:N`) and assigned `CVE-2026-110512`.
