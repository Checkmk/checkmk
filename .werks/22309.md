# Fix reflected XSS in REST API documentation page

Before this fix, the versioned REST API documentation page (`/<site>/check_mk/api/<version>/doc/`) inserted the `<version>` part of the URL into the HTML page without escaping it.
An attacker could craft a link that executed arbitrary JavaScript in the Checkmk GUI with the session of the user opening it.
The documentation page does not require a login, so the attacker does not need a Checkmk account.

Checkmk now only serves the documentation page for known REST API versions and responds with "404 Not Found" otherwise.

This issue was found during internal review.

### Who is Affected

This issue affects all editions of Checkmk in the default configuration.
It can be exploited by an unauthenticated attacker without a Checkmk account.
To exploit it, the attacker needs to make a user who is logged in to Checkmk open a crafted link.
The injected script runs with the permissions of that user.

### Affected Checkmk Versions

* 2.5.0

### Vulnerability Management

We have rated the issue with a CVSS Score of 8.6 High (`CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:A/VC:H/VI:H/VA:H/SC:N/SI:L/SA:N`) and assigned `CVE-2026-121375`.

### Indicators of Compromise

Exploitation attempts are visible in the site's Apache access log as requests to the documentation page with HTML characters in the version part of the URL, for example:
`grep --ignore-case --extended-regexp "/check_mk/api/[^/ ]*(<|>|'|%3C|%3E|%27)[^/ ]*/doc/" var/log/apache/access_log`
