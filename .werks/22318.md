# Fix bulk notifications failing with long host or service names

version    | 3.0.0b1

edition    | community
component  | notifications
level      | 1
compatible | yes

Previously, bulk notifications failed when the values used to separate the
bulks were too long. This happened with long host or service names, or when
many options were selected under _Create separate bulk notifications based on_.
Checkmk stores each bulk in a directory named after these values, and once
that name exceeded 255 bytes, the notification could not be stored and was
never sent.

Such bulks now get a directory name based on a hash of these values.
Notifications with the same values still end up in the same bulk, and the
_Open bulk notifications_ table still shows the readable bulk ID.

A notification that cannot be stored for bulk sending for other reasons,
for example missing permissions in `var/check_mk/notify/bulk`, is not sent.
Checkmk logs the error in `var/log/notify.log` and lists the notification
under _Failed notifications_, so you can fix the cause.
