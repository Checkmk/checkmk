# EC: fix off-by-one error in event limits

key        | value
---------- | ---
date       | 2026-10-22T12:11:03.551761+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

With the event limit action _Stop creating new events_ or _Delete oldest event,
create new event_, the Event Console kept one event more open than the
configured limit. For example, with a limit of 1000 events per host, it opened
1001 events for a host. This affected the global setting _Limit amount of
current events_ as well as the event limits of individual rules and hosts.

The Event Console now keeps at most the configured number of events open.

The actions creating an overflow event still open the event reaching the limit
plus the overflow event, as before. Like the other actions, they now act only
when an event reaches the limit, though. Previously, whenever exactly the
configured number of events was open again, e.g. after archiving only the
overflow event, the next message created one event more than the limit plus
another overflow event and notified again, if configured. Now the Event Console
drops further messages until fewer events than the limit are open, counting
overflow events, too.
