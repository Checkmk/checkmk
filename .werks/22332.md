# EC: slaves use the master's actions

key        | value
---------- | ---
date       | 2026-10-22T13:07:57.646196+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

An Event Console replicating the events of a central Event Console takes over
its rule packs and actions when syncing. It used the synced rule packs right
away, but kept using the actions it knew since the last reload of its own
configuration. So once it had taken over, it didn't know actions added on the
central Event Console: Executing them via a command failed with "The action ...
is not defined", and its rules logged them as undefined instead of executing
them. Changed actions ran in their old version.

The replicating Event Console now uses the synced actions right away. It also
passes the synced rule packs and actions on to Event Consoles replicating from
it right away, instead of only after its configuration was reloaded. In the
Livestatus table `eventconsolestatus`, its column `status_config_load_time` now
shows when it last took over the rule packs and actions of the central Event
Console, as these are the configuration it uses.

Furthermore, a replicating Event Console missed changed rule packs and actions
of the central Event Console if it synced with it while the central Event
Console reloaded its configuration, or in the same second. It only got them
after the next reload of the central Event Console. Now it gets them with its
next sync.
