# Analyze configuration: Fix false WARN on Apache X-Forwarded headers

The test _Apache X-Forwarded-Proto/-Ssl headers_ in _Setup > Maintenance >
Analyze configuration_, introduced with Werk #22268, searched the files below
`/etc/apache2` and `/etc/httpd` for the header names. It reported `WARN` when
the names only appeared in a comment or in a configuration file that is not
enabled. With `APACHE_FORWARDED_HEADERS` set to `manual` it reported `WARN`
when a proxy or load balancer on another host sets the headers, although that
is the setup `manual` is meant for.

The test no longer reads the Apache configuration. It now checks whether the
request that runs it reaches the site with an `X-Forwarded-Proto` header:

* `auto`: `WARN` if the header is missing. Run `omd update-apache-config SITE`
  as root and make sure the Apache module mod_headers is enabled. If the site
  is not reached through the system Apache, e.g. in a container, the proxy in
  front of it has to set the header.
* `manual`: `WARN` if the header is missing. The proxy or load balancer in
  front of the system Apache has to set it.

A `RequestHeader` directive left over from a manual setup is no longer
reported in `auto` mode. Checkmk's own directive takes precedence, so the
leftover does no harm.

The test is no longer executed on the remote sites of a distributed setup.
There it would only see the request of the central site, which need not take
the same way as the requests of the remote site's clients.
