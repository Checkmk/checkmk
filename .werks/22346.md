# Report scheduler: Restore subdirectories in "Store in sub directory"

key        | value
---------- | ---
date       | 2026-10-20T10:25:53.245303+00:00
version    | 2.5.0p18
class      | fix
edition    | pro
component  | reporting
level      | 1
compatible | yes

Since Checkmk 2.4.0p14, the report scheduler percent-encoded the slashes in the
_Store in sub directory_ option of the _Store locally_ action. A path such as
`customer/application` was created as a single directory named
`customer%2Fapplication` instead of two nested directories.

In addition, stored reports whose subdirectory or file name contained such
encoded characters could not be handled on the _Stored reports_ page:
downloading them failed with an error like

_Internal error: [Errno 2] No such file or directory: '.../customer%252Fapplication/report-2026-10-20.pdf'_

and deleting them had no effect, so the report reappeared after reloading
the page. The automatic deletion configured via _Delete after_ was affected
in the same way.

This has been fixed. Slashes in _Store in sub directory_ create nested
directories again, as they did before Checkmk 2.4.0p14. Reports that were
already stored in a directory like `customer%2Fapplication` can be downloaded
and deleted again. They are not moved, so new reports of the same schedule
end up in the nested directories.

The protection against path traversal from Werk #17984 remains in place:
the schedule title (macro `$TITLE$`) still cannot add directories to the
storage location. A schedule whose expanded path points outside your report
archive now fails with an error shown in the scheduler.
