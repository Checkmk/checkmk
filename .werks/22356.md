# omd cp/mv: Keep file permissions when choosing "install" on conflict

key        | value
---------- | ---
date       | 2026-11-15T16:51:49+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | omd
level      | 1
compatible | yes


When you rename or copy a site with `omd mv` or `omd cp`, OMD adapts skeleton
files that contain the site name. If you had modified such a file, OMD asks you
how to resolve the conflict. Choosing *install* replaced your file with the
default version, but the new file did not keep the permissions of the original.

For executable files this broke the site. For example, `etc/init.d/rrdcached`
lost its execute permission, so the site could not start rrdcached.

The *install* choice now keeps the permissions of the existing file.
