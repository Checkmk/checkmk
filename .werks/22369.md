# mk_podman: Fix CLI method for users without a login shell

key        | value
---------- | ---
date       | 2026-10-29T09:21:13.314675+00:00
version    | 2.5.0p19
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

If you use the connection method _CLI (Podman command)_ in the rule
_Podman hosts and containers (Linux)_, the agent plug-in `mk_podman` runs
`podman` as the owner of each container via `su`. Previously, `su` used the
login shell of this user. Service users often have `/usr/sbin/nologin` or
`/bin/false` as their login shell. For these users the command failed, and
the plug-in did not report their containers.

The plug-in now uses `/bin/sh` if the login shell of the user is not listed
in `/etc/shells`. All other users keep their own login shell, as before.

To get the fix, redeploy the agent plug-in on the affected hosts.
