# Rescheduling Check_MK inventory skipped the Check_MK service

In the views, rescheduling the _Check_MK Discovery_ service first
reschedules the _Check_MK_ service and waits for it, so that the discovery
works with fresh agent data. Werk #13843 meant to do this for both names of the
discovery service, but sites that still use the old name _Check_MK inventory_
never got it: rescheduling that service skipped the _Check_MK_ service, so the
discovery could work with cached agent data.

Rescheduling _Check_MK inventory_ now reschedules the _Check_MK_ service first,
just like _Check_MK Discovery_.
