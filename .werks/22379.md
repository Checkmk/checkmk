# Rescheduling a service with a backslash in its name no longer fails

key        | value
---------- | ---
date       | 2026-11-23T15:02:08.355137+00:00
class      | fix
edition    | community
component  | multisite
level      | 1
compatible | yes

When you rescheduled a service whose name contains a backslash from a classic
view, for example a Windows task named after its path, the GUI answered "The
check to reschedule was not found." The service was there all along: the view
passed its name on with every backslash doubled.

The name now arrives as it is, so these services are rescheduled like any other.
