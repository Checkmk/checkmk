# brocade_mlx_fan: do not let a nameless fan break service discovery

key        | value
---------- | ---
date       | 2026-09-22T06:09:13.169948+00:00
version    | 2.5.0p15
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

On some Brocade MLX switches the fan table contains a row with no fan number.
Checkmk had no name to give the resulting service, and the service discovery of
the **whole host** failed with
`TypeError: 'item' must be a non empty string or ommited entirely, got ''`. The
`Check_MK Discovery` service reported a crash instead of a result, so no service
on that host could be discovered any more.

Fan rows without a fan number are now skipped. Discovery works again and all
other fans of the switch are discovered and monitored as before.

A fan reported without a number is not monitored, because there is no stable way
to name its service. If the description of such a fan carries an RPM reading, it
is dropped for the same reason it was dropped before: the reading changes and
would rename the service on every discovery.
