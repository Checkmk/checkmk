# GCP Redis: CPU utilization was 60 times too high

class      | fix
edition    | ultimate
component  | checks
level      | 2
compatible | no

Previously, the service `Redis - <instance> - CPU` showed a CPU
utilization that was 60 times too high, for example 2361% instead of 39%.
With the default levels of 80%/90%, the service was always CRIT.

The special agent read the CPU-seconds of one minute, and Checkmk showed
this value as a percentage. The agent now reads the CPU-seconds per
second, so 100% means that one CPU core is fully used.

For an instance with replicas, the value was also the sum of all nodes.
The levels now apply to the busiest node. The service details show the
utilization of each node.

The graph keeps the old values from before the update.

## What you need to do

If you raised the levels in the rule "GCP/Redis CPU utilization" to work
around the wrong values (for example to 4800%/5400%), set them back.
If you do not, the service will not warn any more. If you disabled the
service, enable it again.

If the special agent runs on a site that you did not update yet, the
service is UNKNOWN until you update that site.
