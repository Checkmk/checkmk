# GCP Redis: memory and hit ratio added up all nodes

Previously, for a Redis instance with replicas (Standard tier), the
services `Redis - <instance> - memory` and `Redis - <instance> - hitratio`
added up the values of all nodes. For example, two nodes with a memory
utilization of 45% each showed 90%, and the hit ratio could go above 100%.

The services now show these values:

* Memory utilization and system memory utilization: the levels apply to
  the node with the highest value. The service details show the value of
  each node.
* Hit ratio: the value of the primary node. Without read replicas, only
  the primary serves reads. With read replicas, the replicas also serve
  reads, and the service does not include them. If GCP sends no value for
  the primary node, for example during a failover, the service is UNKNOWN.

The CPU utilization had the same problem. See
[Werk #22413](https://checkmk.com/werk/22413).

The graphs keep the old values from before the update.

## What you need to do

If you raised the levels in the rules "GCP/Redis memory utilization" or
"Redis/Hitratio" to work around the summed values, set them back.
If you do not, the services may not warn any more.
