# cmk -II: Keep the services and host labels of failed data sources

key        | value
---------- | ---
date       | 2026-10-06T08:30:08.235584+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | core
level      | 1
compatible | yes

Previously, `cmk -II` removed the services and host labels of every data source that
could not be contacted. A single timeout, a failed address lookup or a missing cache file
was enough: the source delivered nothing, so all of its services were taken for vanished
and deleted from the host.

A failed data source tells you nothing about its services, so `cmk -II` no longer acts on
it. For a host with a failed data source, `cmk -II` now behaves like `cmk -I`: the
services and host labels found by the other data sources are added, while existing
services and host labels are neither removed nor changed. `cmk -I` also keeps the host
labels of a failed data source now. A warning tells you which hosts this applies to.

As before, the command exits with 1 if a data source of any host failed. Once all data
sources of the host can be contacted again, run `cmk -II` once more to remove services
that have really vanished.

Bulk and periodic service discovery are not affected. They already refuse to change a
host as long as one of its data sources fails.
