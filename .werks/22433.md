# folder endpoints failed if a network scan referred to a deleted user

key        | value
---------- | ---
date       | 2026-10-28T11:52:13+00:00
version    | 2.4.0p40
class      | fix
edition    | cre
component  | rest-api
level      | 1
compatible | yes

If the network scan of a folder was set to run as a user who was deleted
later, every REST API request that returned this folder failed with
`500 Internal Server Error` and "Mismatch between endpoint and internal data
format". This included listing all folders recursively, so a single such
folder broke the folder listing for the whole site. The same happened if the
criticality tag group was added or removed after the network scan settings of
a folder were saved.

The REST API now returns the stored network scan settings unchanged. Creating
or updating a folder still requires `run_as` to be an existing user and
`tag_criticality` to match the criticality tag group.

To make the network scan of such a folder work again, select an existing user
as "Run as" in the network scan settings of the folder.
