# Quick Setup: Service discovery for hosts on a remote site was applied on the central site

key        | value
---------- | ---
date       | 2026-10-07T11:07:05.645734+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | wato
level      | 1
compatible | yes

If a Quick Setup (for example for AWS, Azure, GCP or Proxmox VE) was run for a host
that is monitored on a remote site, the service discovery at the end of the
setup ran on the remote site, but its result was applied on the central
site. The discovered services and host labels were written to the central
site, while the remote site, which monitors the host, did not receive them.

This problem was introduced in Checkmk 2.5.0. The result is now applied on
the site that the Quick Setup targets.

If you created a Quick Setup configuration for a remote site with an affected
version, run a service discovery for its hosts to get the services monitored.
The autochecks left behind on the central site in `var/check_mk/autochecks/`
do no harm, because the central site does not monitor these hosts, but you
may remove them. Do not remove files in `var/check_mk/discovered_host_labels/`:
the central site keeps synchronized copies of the remote hosts' host labels
there.
