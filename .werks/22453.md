# Fix crash of views when ntopng returns a non-JSON login response

Views with host context, for example "Service problems", could crash with
"Internal error: Expecting value: line 1 column 1 (char 0)". This happened when
ntopng answered Checkmk's login request with something other than JSON, for
example an HTTP 502 error page from a proxy. Only users with an ntopng username
set in their user settings were affected. Until the ntopng connection was
deactivated, every view with host context was unusable for them.

Checkmk already had error handling for this case, but it caught the wrong
exception type. Those views now render normally and just leave out the ntopng
menu. The detection of the ntopng API version had the same problem and is fixed
too.
