# Relay: Core accepts results from many relay hosts at once

key        | value
---------- | ---
date       | 2026-10-29T09:58:41.560149+00:00
version    | 3.0.0b1
class      | fix
edition    | ultimate
component  | relay
level      | 1
compatible | yes

Previously, relays with many hosts lost part of their monitoring results.
For example, one relay with 404 SNMP hosts got 148 of its 404 results per
minute through. The rest were dropped, and services of relay hosts went
stale. Adding more relays didn't help, because all results take the same
path into the core.

There were two causes. The monitoring core accepted relay results over a
single connection at a time. When that connection was busy, the agent
receiver gave up at once and answered the relay with HTTP 502 instead of
waiting. You could see this as `POST /relays/<id>/monitoring` requests
with status 502 in `var/log/agent-receiver/access.log`.

Both are fixed. The core now accepts results over many connections in
parallel. When the core is busy, the agent receiver now waits up to 5
seconds for it.
