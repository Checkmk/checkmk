# Veeam CDP jobs: Show real last sync instead of misread next run

The _VEEAM CDP Job_ services reported _Time since last CDP Run_ based on the
wrong value. The Windows agent plug-in sends the policy's next scheduled run
(`NextRun`), but the check treated it as the time of the last run. As a result,
the age shown was meaningless, and a regular future `NextRun` turned the service
`WARN` with "The timestamp of the file is in the future".

In addition, a failing CDP policy was shown as `OK`: on Veeam Backup &
Replication 13 the policy state is only `InitialSync`, `Running` or `Disabled`,
so the check never saw a failure. `InitialSync` was reported as `UNKN`.

## What changed

The services now show:

* the policy state, with `InitialSync` being `OK`
* the result of the last policy run (`Warning` is `WARN`, `Failed` is `CRIT`)
* the next scheduled run
* the time since the last CDP sync. The plug-in takes the time of the most
  recent restore point for each replica of the policy and reports the oldest
  one, since the replica lagging behind the most determines your RPO.

The ruleset _Veeam: Time since last CDP run_ is renamed to _Veeam: Time since last
CDP sync_. Your existing rules are kept and now apply to the time since the last
CDP sync. Disabled policies stay `OK`: they are not checked for their age, and
the result of their last run is only shown in the details.

## Action required

Redeploy the _Veeam_ agent plug-in (`veeam_backup_status.ps1`) on your Veeam
servers, e.g. by baking and updating the agents. Until then, the services only
show state and next run, and your age levels are not applied.

Also review your levels: the default of 30/48 hours is very generous for CDP
policies whose RPO is usually measured in seconds or minutes.

Note that the updated agent plug-in requires a Checkmk server that includes this
werk. Older servers will lose the _VEEAM CDP Job_ services.
