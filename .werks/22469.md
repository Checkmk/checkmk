# WMI checks: accept levels that are stored as a list

key        | value
---------- | ---
date       | 2026-09-22T08:09:24.031127+00:00
version    | 2.4.0p38
class      | fix
edition    | cre
component  | checks
level      | 1
compatible | yes

Depending on how the levels of a WMI based check were configured, they reached
the check as a list instead of a pair of values. If only the upper levels were
set, the service went UNKNOWN with
`TypeError: can only concatenate list (not "tuple") to list` and produced a
crash report instead of a result. Seen for example on
`DotNet Memory Management`, but every check using the WMI levels helper was
affected.

The levels are now accepted in either form, and the affected services are
monitored against them again.
