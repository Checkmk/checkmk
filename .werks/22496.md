# dell_idrac_power: detect the iDRAC generation via racType

key        | value
---------- | ---
date       | 2026-10-08T08:16:57.866257+00:00
version    | 2.4.0p39
class      | fix
edition    | cre
component  | checks
level      | 1
compatible | yes

Werk #20029 made the plugin choose the value scope of
`powerUnitRedundancyStatus` by the iDRAC generation, which it read from
`racShortName` (`.1.3.6.1.4.1.674.10892.5.1.1.2.0`).

Not every iDRAC names its generation there. An iDRAC9 on a 16th generation
PowerEdge answers a plain `iDRAC`, which the plugin took to mean "not one of
the older generations", and therefore decoded the redundancy status with the
iDRAC10 value scope. That scope does not define `full(3)`, the value such a
device reports. Although the power supplies were in fact fully redundant, the
service "Power Supply Redundancy" went UNKNOWN with `Status: n/a`.

The plugin now reads `racType` (`.1.3.6.1.4.1.674.10892.5.1.1.7.0`) first.
That OID names the generation on every device we have seen, including those
whose `racShortName` does not, and it has the same meaning in both MIB
versions. `racShortName` is only consulted if `racType` does not name a
generation.

A redundancy status that the detected generation does not define is still
reported as UNKNOWN, but instead of `Status: n/a` the service now names both
the value and the assumed MIB:

```
Status: undefined value 3 (assuming the MIB for iDRAC10 or newer)
```

To benefit from this change, no manual action is needed.
