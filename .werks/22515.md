# Averaging checks: Fix ZeroDivisionError after time anomalies

key        | value
---------- | ---
date       | 2026-09-29T09:04:15.680784+00:00
version    | 2.5.0p15
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

Checks that average their values over time could crash with
`ZeroDivisionError: float division by zero`. This was seen with the
`Proxmox VE CPU Utilization` service when averaging is configured: it uses the
uptime of the VM as its clock, and if the reported uptime stepped back and then
returned to exactly the time at which averaging had started, the next check
crashed.

This case is now treated like other time anomalies, and the service keeps
reporting the averaged value.
