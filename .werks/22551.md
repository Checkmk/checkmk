# Agent controller: Secret files were briefly readable by local users

The agent controller `cmk-agent-ctl` stores the private keys of its TLS connections in the file `registered_connections.json`.
When a `cmk-agent-ctl` command changed the connections, the controller created this file with the permissions that the umask of the calling process allowed.
With the usual umask `0022`, every local user could read the file.
The controller restricted the permissions to `0600` only after it had written the keys.
During this short time, a local user could read the private keys.
With such a key, the local user could authenticate as the monitored host to the agent receiver of the Checkmk site.

In Checkmk 2.5.0 and later, the controller handled the file `.pwd` in the same way.
The controller writes `.pwd` when it registers the agent updater.
The file holds the password of the Checkmk user that was used for the registration.
A local user who read the file could act on the Checkmk site with the permissions of this Checkmk user.

The controller now creates both files with the permissions `0600` from the start.

### Who is Affected

All editions, but only Linux hosts on which someone manually ran a `cmk-agent-ctl` command that changes the connections, for example `register`, `import` or `delete-connection`.
The agent controller service itself is not affected, because it runs with the umask `0077`.
The controller writes `.pwd` only on hosts with the agent updater.

In the multi-directory deployment, the controller keeps its files in `/var/lib/cmk-agent`, which every local user can usually read.
In the single-directory deployment, only members of the agent user's group can read the directory `runtime/controller`.
On such hosts, only these members could read the files.

### Affected Checkmk Versions

* 2.5.0
* 2.4.0
* 2.3.0 (EOL)

### Vulnerability Management

We have rated the issue with a CVSS Score of 4.8 Medium (`CVSS:4.0/AV:L/AC:L/AT:P/PR:L/UI:N/VC:L/VI:L/VA:N/SC:H/SI:H/SA:N`) and assigned `CVE-2026-133714`.

This issue was found by internal review.

### Mitigations

If updating is not possible, set the umask `077` before you run `cmk-agent-ctl` manually, for example with `sudo sh -c 'umask 077 && cmk-agent-ctl register ...'`.
If untrusted users have accounts on such a host, change the password of the Checkmk user that was used for registrations on this host.
