# Agent bakery: RPM packages baked on Ubuntu 26.04 failed on older rpm

key        | value
---------- | ---
date       | 2026-11-24T13:16:41.222676+00:00
class      | fix
edition    | pro
component  | agents
level      | 1
compatible | yes

On a Checkmk site that runs on Ubuntu 26.04, the agent bakery created RPM packages that many hosts could not install.
On hosts with an rpm version older than 4.12, the installation failed with the following message:

`error: Failed dependencies: rpmlib(LargeFiles) <= 4.12.0-1 is needed by check-mk-agent-<version>-<hash>.noarch`

This affected, for example, RHEL 7, CentOS 7 and systems based on them, such as XCP-ng.
Automatic agent updates failed on these hosts for the same reason.

The agent bakery creates RPM packages with the `rpmbuild` of the Checkmk server's operating system.
Ubuntu 26.04 ships rpm 6, which creates packages in the RPM v6 format by default.
According to the rpm project, rpm versions older than 4.14 cannot install packages in this format.

The agent bakery now always creates RPM packages in the RPM v4 format, the default of all rpm versions before 6.
Baked RPM packages therefore have the same requirements as before, see [Werk #17093](https://checkmk.com/werk/17093).

After the update, bake and sign the agents as usual.
The agent bakery then creates all packages anew.
