# mk-oracle: Plug-in files renamed to mk-oracle-v2, AIX and Solaris files offered for download

key        | value
---------- | ---
date       | 2026-11-23T09:36:55.059867+00:00
class      | fix
edition    | community
component  | agents
level      | 1
compatible | no

The files of the new Oracle agent plug-in ([Werk #22245](https://checkmk.com/werk/22245)) had different names on the Checkmk site than on the monitored host.
The Agent Bakery deploys them as `mk-oracle-v2`, `mk-oracle-v2_sync` and `mk-oracle-v2_async`.
The page _Setup > Agents > Windows, Linux, Solaris, AIX > Related > Other operating systems_ offered the same files as `mk-oracle`, `oracle_unified_sync` and `oracle_unified_async`.
Anyone installing the plug-in manually had to rename the binary, because the wrapper scripts call it as `mk-oracle-v2`.

The files on the site now have the names they are deployed under:

 * `mk-oracle` is now `mk-oracle-v2`. The same applies to `mk-oracle.exe`, `mk-oracle.aix` and `mk-oracle.solaris`.
 * `oracle_unified_sync` is now `mk-oracle-v2_sync`.
 * `oracle_unified_async` is now `mk-oracle-v2_async`.
 * `oracle_unified_async_custom_metrics` is now `mk-oracle-v2_async_custom_metrics`.

The wrapper scripts keep their suffixes `.ps1`, `.aix` and `.solaris`. The configuration file `mk-oracle.yml` and the files of the legacy plug-in `mk_oracle` keep their names.

In addition, the download page did not offer the AIX and Solaris files of the plug-in at all. They are now listed in the section _Oracle_.

Hosts that get the plug-in from the Agent Bakery are not affected, because the names of the deployed files do not change.
If you download these files or copy them from the site directory `~/lib/python3/cmk/plugins/oracle/agents/` with your own scripts, adapt the file names there.
