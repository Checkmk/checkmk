# Inline SNMP: Fix fetcher crash when an SNMP request times out

key        | value
---------- | ---
date       | 2026-11-04T11:00:00.000000+00:00
version    | 2.5.0p20
class      | fix
edition    | pro
component  | inline-snmp
level      | 1
compatible | yes

With the inline SNMP backend, fetcher processes could crash and leave a core
dump when the fetcher timeout hit while an SNMP request was in flight. The
process then aborted with a message like `free(): invalid pointer`, `free():
invalid size` or `double free or corruption`, with a backtrace ending in
`snmp_free_pdu()`, or it died with a segmentation fault. Both happened inside
the netsnmp Python module.

The fetcher timeout could take effect while the netsnmp Python module was
processing a request, which the module does not handle. Hosts with slow
responses or long SNMP timeouts and retries, for example SNMPv3 devices, were
affected most.

The inline SNMP backend now holds the fetcher timeout back until the current
SNMP request has finished. This does not make fetches take longer: the
timeout could not interrupt a running SNMP request before either. The fetcher
timeout is reported as before, without the crash.
