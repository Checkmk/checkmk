# Kubernetes: no crash on future start time

key        | value
---------- | ---
date       | 2026-10-06T05:17:45.133428+00:00
version    | 2.4.0p39
class      | fix
edition    | cre
component  | checks
level      | 1
compatible | yes

If the clock of a Kubernetes cluster ran ahead of the clock of the
Checkmk server, the `Container` service of a running container could
crash with `ValueError: Cannot render negative timespan`, because the
container appeared to have been started in the future.

The service now goes to UNKNOWN, states that the container is running
and how far its start time lies in the future, and asks you to check
the system time.
