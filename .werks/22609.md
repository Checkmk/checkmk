# Inline timelines merged too few state changes at the end into a chaotic period

key        | value
---------- | ---
date       | 2026-10-27T07:06:09.840265+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | multisite
level      | 1
compatible | yes

Inline availability timelines merge runs of very short state changes into
one "chaotic" period, but only if the run has at least four state changes.
A run at the very end of the time range was merged from just two state
changes, so the end of a timeline could show a chaotic period where the same
run anywhere else would not.

Runs at the end of the time range now follow the same rule as all other runs.
