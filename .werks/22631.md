# Keep agent download token on failure

If the agent download from the generated install command failed because
the agent package was not available yet, the one-time download token was
used up anyway. Running the same command again then failed with HTTP 401.
With the Agent Bakery this happened with "Agent hash not found" when no
agent was baked yet. Without it, a missing agent package caused an
internal error instead of HTTP 404.

If the agent package is not available, the download now answers with an
error and the token stays valid, so the same command can be run again
once the package is there. Other errors, like an unknown host or missing
permissions, still use up the token.

Running an install command with a token that was already used or has
expired now explains this and points to the host's agent dialog to
generate a new token.
