# Automation helper stopped noticing configuration changes after a failed reload

compatible | yes

After a failed configuration reload, the automation helper stopped noticing changes to the configuration until it was restarted. A reload failed, for example, if a `.mk` file contained an error, or if a configuration file was removed while the configuration was being reloaded.

Automations then used outdated configuration. For example, hosts created after the failed reload remained unknown to the automation helper, and their service discovery failed with "Failed to lookup IPv4 address of ... via DNS".

The automation helper now keeps noticing changes after a failed reload. It logs the error and retries the reload on the next change or automation. Until the configuration can be loaded again, automations report the error.

If you cannot update yet, restart the automation helper to make it notice changes again: `omd restart automation-helper`.
