# Inline timelines drew chaotic periods after the following gap

key        | value
---------- | ---
date       | 2026-10-27T07:09:33.888080+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | multisite
level      | 1
compatible | yes

If a run of very short state changes in an inline availability timeline was
followed by a period without monitoring data, the bar drew the "chaotic"
period after the unmonitored one, so it appeared later than it actually
happened. A short state change after such a gap could also be merged into
the chaotic period before the gap.

A chaotic period now ends where the unmonitored period starts and is drawn
before it, both in the middle and at the end of the timeline.
