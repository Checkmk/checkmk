# mk_oracle: Fix corrupted or truncated output containing backslashes

key        | value
---------- | ---
date       | 2026-11-25T14:14:41.820757+00:00
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

The agent plug-in `mk_oracle` for Linux, AIX and Solaris interpreted backslash
sequences in the output of SQL*Plus instead of passing them on unchanged.

Values containing a backslash were altered. For example, the data file path
`C:\temp\new\data01.dbf` was turned into a tab and a line break, and a `\c`
as in `D:\oradata\control01.dbf` discarded all output that followed. In that
case the affected section and all sections after it were missing in the agent
output, and the corresponding services became stale or vanished.

This mainly affected the remote monitoring of Oracle databases running on
Windows. It could also occur with databases on other platforms, because the
services _ORA ... Locks_ and _ORA ... Long Active Sessions_ show the machine
and operating system user of the client, such as `DOMAIN\user`.

The output of the built-in sections is now passed on unchanged.

The output of custom SQLs is not changed: backslash sequences in it are still
interpreted as before. To print a literal backslash from a custom SQL, double
it in the statement, for example with `replace(file_name, '\', '\\')`.

To benefit from this fix, the agent plug-in has to be updated on the affected
hosts.
