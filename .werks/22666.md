# REST API: Fix crash on notification rule fields enabled without value

Creating or editing a notification rule through the REST API failed with an internal server error (in most cases `KeyError: 'value'`) if one of the following fields was sent with `"state": "enabled"` but without a `value`:

* `match_services` and `match_exclude_services` in the conditions
* `match_syslog_priority` and `match_syslog_facility` in the Event Console alert condition
* `the_following_users` and `restrict_by_custom_macros` in the contact selection
* `notification_bulking` and `bulk_outside_timeperiod` in its parameters
* `url_prefix_for_links_to_checkmk` in the parameters of all notification methods that offer it
* `from_details`, `reply_to`, `subject_for_host_notifications` and `subject_for_service_notifications` in the parameters of the HTML and ASCII email notification methods
* `insert_html_section_between_body_and_table` and `enable_sync_smtp` in the parameters of the HTML email notification method
* `syslog_facility_to_use` in the parameters of the notification method that forwards to the Event Console
* `responsible_teams`, `actions` and `tags` in the parameters of the Opsgenie and Jira Service Management Operations notification methods
* `additional_responders` in the parameters of the Jira Service Management Operations notification method
* `state_acknowledgement`, `state_downtime` and `state_recovery` in the management type parameters of the ServiceNow notification method

The REST API now rejects such requests with status code 400.
