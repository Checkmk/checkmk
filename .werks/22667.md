# REST API: Reject notification rule HTTP proxy enabled without value

key        | value
---------- | ---
date       | 2026-11-12T17:03:33.732514+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | rest-api
level      | 1
compatible | no

When creating or editing a notification rule through the REST API, the `http_proxy` parameter of a notification method could be sent with `"state": "enabled"` but without a `value`. Such a request was accepted, but the rule was saved without an HTTP proxy.

The REST API now rejects such requests with status code 400.

Scripts that send `http_proxy` this way must either add a `value` or send `"state": "disabled"`. The latter results in the same rule as before.
