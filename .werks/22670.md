# REST API: Slack notification rule ignored disable_ssl_cert_verification

When creating or editing a notification rule with the Slack or Mattermost notification method through the REST API, `disable_ssl_cert_verification` was ignored.
Instead, the state of `url_prefix_for_links_to_checkmk` decided whether the SSL certificate verification was disabled:

* With `url_prefix_for_links_to_checkmk` disabled, the verification stayed enabled, even if `disable_ssl_cert_verification` was enabled.
* With `url_prefix_for_links_to_checkmk` enabled, the verification was disabled, even if `disable_ssl_cert_verification` was disabled.

In the second case, notifications were sent to the webhook URL without checking the certificate of the receiving server.

Now `disable_ssl_cert_verification` alone controls the SSL certificate verification.

Existing rules are not changed.
If you created or edited Slack or Mattermost notification rules through the REST API, check the option _Disable SSL certificate verification_ in the notification method parameters of these rules.

### Who is Affected

All editions.
A site is affected if it has Slack or Mattermost notification rules that were created or edited through the REST API with `url_prefix_for_links_to_checkmk` enabled.
Rules created or edited only in the GUI are not affected.

### Affected Checkmk Versions

* 2.5.0
* 2.4.0
* 2.3.0 (EOL)

### Vulnerability Management

We have rated the issue with a CVSS Score of 6.3 Medium (`CVSS:4.0/AV:N/AC:L/AT:P/PR:N/UI:N/VC:L/VI:N/VA:N/SC:N/SI:L/SA:N`) and assigned `CVE-2026-132041`.

This issue was found by internal review.

### Mitigations

Without updating, check the affected rules as described above and clear the option _Disable SSL certificate verification_ where it is not wanted.
When editing these rules through the REST API, do not enable `url_prefix_for_links_to_checkmk`, or edit them in the GUI instead.
