# Bazel remote cache: certificate verification setting had no effect

The "SSL certificate verification" setting of the rule "Bazel remote cache"
had no effect. The special agent never verified the certificate of the Bazel
cache server, even when the setting was enabled, and sent the configured
user and password over this unverified connection. An attacker in a
position to intercept the connection could impersonate the cache server and
obtain these credentials.

The special agent now verifies the certificate when the setting is enabled.
Existing rules keep the setting shown in the GUI.

This change is incompatible if you enabled "SSL certificate verification" and
your Bazel cache server uses a certificate that the Checkmk site does not
trust, for example a self-signed one. The special agent then fails with a
certificate error. Either make the site trust the certificate, or disable the
setting in the rule.

### Who is Affected

All editions, but only sites that monitor a Bazel remote cache over HTTPS with
the rule "Bazel remote cache" and have "SSL certificate verification" enabled.

### Affected Checkmk Versions

* 2.5.0
* 2.4.0
* 2.3.0 (EOL)

### Vulnerability Management

We have rated the issue with a CVSS Score of 6.9 Medium
(`CVSS:4.0/AV:N/AC:L/AT:P/PR:N/UI:N/VC:L/VI:L/VA:N/SC:H/SI:L/SA:N`) and assigned
`CVE-2026-132040`.

This issue was found by internal review.

### Mitigations

If updating is not possible, configure the rule with a user that has read
access to the Bazel cache only.
