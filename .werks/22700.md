# BI: Unreachable 'Count OK' levels prevent acknowledgement

key        | value
---------- | ---
date       | 2026-11-10T14:17:35.678812+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | bi
level      | 1
compatible | yes

If a BI rule uses the aggregation function _Count the number of nodes in
state OK_ and its levels require more OK nodes than the rule has child
nodes, the aggregate can never be `OK`. Such aggregates were never
considered acknowledged, even if all of their child nodes were
acknowledged. If you enabled the computation option _Show downtime only
when all current problems are covered_, they were also never considered
to be in a scheduled downtime.

Checkmk decides both by treating the acknowledged (or in downtime) child
nodes as `OK` and checking whether that makes the aggregate `OK`. Since
these aggregates never become `OK`, the check always failed. Checkmk now
compares against the state the aggregate has when all of its child nodes
are `OK` instead:

* If only the OK level is out of reach, the aggregate is at best `WARN`.
  It is acknowledged, or in downtime, if its child nodes cover everything
  that makes it worse than `WARN`.
* If both levels are out of reach, so that the aggregate is always `CRIT`,
  all child nodes must be acknowledged, or in downtime.

If you use the special agent rule _BI aggregations_ with the option
_State, if BI aggregate is acknowledged_ or _State, if BI aggregate is in
scheduled downtime_, the affected `Aggr` services may now report the
configured state instead of `CRIT` or `WARN`. You don't need to change
anything.

See [Werk #22689](https://checkmk.com/werk/22689) for a related fix of the
service period and downtime of these aggregates.
