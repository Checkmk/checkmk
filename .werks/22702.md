# cmk-product-usage: No cron mails on unreachable analytics server

edition    | community

compatible | yes

Previously, if `cmk-product-usage --cron` could not reach `analytics.checkmk.com`,
it wrote the error to STDERR, so cron sent you a mail every 30 minutes, and
`var/log/product_usage_analytics.log` filled up with chains of tracebacks.

A common cause is a DNS block list that contains `analytics.checkmk.com`. The DNS
server answers with `0.0.0.0`, which the resolver turns into `127.0.0.1`. The
upload then ends at the local web server and fails with an error that does not
point to the cause:

_certificate verify failed: Hostname mismatch, certificate is not valid for 'analytics.checkmk.com'_

This has been fixed:

* The cron job no longer writes to STDERR.
* A failed connection is logged in one line that names the likely cause. If the
  host name resolves to a loopback address or to `0.0.0.0`, the message points
  to the DNS block list. If it does not resolve at all, the message says so.
* The collected data stays on the site and is sent with the next run. The next
  run is planned as usual instead of being retried every 30 minutes.
* Other unexpected errors create a crash report of the type `product-usage`.
  The log names its crash ID, so you can find the report and send it to us.

To send product usage analytics from a site behind such a DNS filter, allow
`analytics.checkmk.com` in the filter or configure a proxy for the upload.
