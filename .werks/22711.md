# New permission "See pending changes" for the REST API

key        | value
---------- | ---
date       | 2026-10-28T23:05:12.407709+00:00
version    | 3.0.0b1
class      | feature
edition    | community
component  | rest-api
level      | 1
compatible | yes

You can now let a role list the pending changes through the REST API without
allowing it to activate them. The new permission _See pending changes_, next to
_Activate configuration_ in the Setup permissions, grants access to the endpoint
_Show all pending changes_ (`GET /domain-types/activation_run/collections/pending_changes`)
on its own. Until now, this endpoint required _Activate configuration_. Roles with
_Activate configuration_ can still list the pending changes, with or without the
new permission.

The built-in roles _Administrator_ and _Normal monitoring user_ have the new
permission by default, and custom roles inherit it from the role they are based
on. The update revokes it from every role that has _Activate configuration_
revoked, so these roles still can't list the pending changes.

The permission only applies to the REST API. Revoking it doesn't hide the
pending changes in the GUI.
