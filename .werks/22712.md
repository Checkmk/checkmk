# Changes slideout exposed pending changes to all users

version    | 2.5.0p20
class      | security
edition    | community

compatible | yes

Any logged-in user could read all pending changes and the status of all sites by calling the page behind the _Changes_ slideout of the main menu (`ajax_sidebar_get_sites_and_changes.py`) directly, including users with the built-in role _Guest user_.
The response contained the text, author and time of every pending change, which name hosts, folders, rules and users, and per site its version, its online and login status and the result of its last activation.
Only the menu entry was limited to users with the permission _Activate configuration_; the page behind it checked no permission.

The page now requires _Activate configuration_ or _See pending changes_ (see [Werk #22711](https://checkmk.com/werk/22711)), like the REST API endpoint that lists the pending changes.
The page that counts the pending changes for the menu badge (`ajax_sidebar_get_number_of_pending_changes.py`) checks the same permissions.
The menu entry is still shown only to users with _Activate configuration_.

This issue was found during internal review.

### Who is Affected

All editions.
A site is affected if it has users whose roles have neither _Activate configuration_ nor access to Setup, for example users with the built-in role _Guest user_ or custom read-only roles.
Users with access to Setup could already see the pending changes on the page _Activate pending changes_.

### Affected Checkmk Versions

* 2.5.0

### Vulnerability Management

We have rated the issue with a CVSS Score of 5.3 Medium (`CVSS:4.0/AV:N/AC:L/AT:N/PR:L/UI:N/VC:L/VI:N/VA:N/SC:N/SI:N/SA:N`) and assigned `CVE-2026-123789`.
