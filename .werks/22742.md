# logwatch: don't crash if the worst message is an empty line

key        | value
---------- | ---
date       | 2026-10-15T09:16:18.906654+00:00
version    | 2.5.0p18
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

A `Log` service crashed with
`ValueError: 'summary' must be non-empty str or None, got ''` if the most
severe message of the log file was an empty line, for example when a
pattern classified an empty line as WARN or CRIT.

The service now shows the number of messages per state as summary, e.g.
`1 WARN messages`.
