# Bazel cache: retry version lookup hourly

key        | value
---------- | ---
date       | 2026-11-16T11:48:32.058367+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

The Bazel remote cache special agent looks up the bazel-remote release
tags on GitHub to report version information. If this lookup failed,
the agent repeated it on every run. This quickly used up the GitHub
limit of 60 unauthenticated requests per hour, and on sites without
internet access every run could wait up to 30 seconds for the request
to time out. Unexpected answers from GitHub, such as a response that
is not JSON or a tag name that is not a version number, crashed the
agent.

The agent now waits one hour before it retries a failed lookup, or the
configured version cache interval if that is shorter. On unexpected
answers it skips the version information instead of crashing; the
cache metrics are reported as usual. Tags that are not a version
number, such as "latest", are ignored. Older bazel-remote releases are
now recognized as well (up to the last 100 tags).

If you run the agent with `--debug`, it always retries the lookup and
shows the error.

This continues the fix from [Werk #23009](https://checkmk.com/werk/23009).
