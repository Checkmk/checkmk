# Check email: fix broken "Clean up messages" values from older versions

key        | value
---------- | ---
date       | 2026-10-31T06:16:36.256629+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

Some versions stored invalid values for the option *Clean up messages* in
*Check email* rules that use *Forward mails as events to Event Console*.
Depending on the version that last saved or updated the rule, you were affected
like this:

* **2.4.0p23 to 2.4.0p29 and 2.5.0b1 to 2.5.0p3**: With *Delete all processed
  messages belonging to this check* selected, the rule could no longer be used
  to create the active check. Updating logged "validation errors for
  Parameters" and the service went stale.
* **2.4.0 to 2.4.0p22**: Editing or updating such a rule turned the option into
  *Move all processed messages to subfolder*, with a folder literally named
  `('delete', 'delete')`. Mails were moved into that folder instead of being
  deleted. Rules that already moved mails to a subfolder got a mangled folder
  name such as `('move', 'INBOX')` in the same way.

The update now restores the intended setting for all of these values. You don't
need to do anything. If mails piled up in a folder called `('delete', 'delete')`
or similar, you can delete that folder in your mailbox.
