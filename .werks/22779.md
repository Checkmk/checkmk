# Check HTTP web service: Resolve macros in proxy server name

key        | value
---------- | ---
date       | 2026-11-24T06:40:51.484213+00:00
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

The _Check HTTP web service_ check now resolves host macros such as
`$HOSTNAME$` or `$HOSTADDRESS$` in the server name of an explicitly
configured HTTP proxy.

Until now, the macro was passed to the check literally, for example as
`--proxy-url http://$HOSTADDRESS$:3128`. The check then failed with a
DNS lookup error. This mainly hit rules migrated from the deprecated
_Check HTTP service_ ruleset, where macros in the proxy address worked.
