# Rule search: survive invalid host regex

key        | value
---------- | ---
date       | 2026-10-19T10:38:36.355544+00:00
version    | 2.4.0p38
class      | fix
edition    | cre
component  | wato
level      | 1
compatible | yes

If a rule had an explicit host condition with an invalid regular
expression, for example `~*foo`, searching rules by host in the
rule search crashed with `error: nothing to repeat at position 0`.

The search now shows a warning that links to the affected rule, as
it already did for invalid regular expressions in service conditions
and in the full text search, and continues with the other rules.
