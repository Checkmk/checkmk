# EC: slaves count the master's events

key        | value
---------- | ---
date       | 2026-10-22T14:01:07.222462+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

An Event Console replicating the events of a central Event Console takes over
its events with every sync. Its counters for the event limits, however, kept
counting the events it had when it was started. As a consequence, such an Event
Console:

- showed a wrong number of current events in its service _OMD [site] Event
  Console_, and event limits that were wrongly shown as active or inactive,
- enforced its event limits against these numbers once it had taken over, so it
  could open more events than allowed or stop opening them too early, and
- logged an error with a traceback in `var/log/mkeventd.log` when it removed a
  synced event of a host or rule it hadn't counted any events for, e.g. when you
  archived the event after a takeover or when its lifetime expired. Archiving
  several events at once stopped at such an event.

The counters now match the synced events.
