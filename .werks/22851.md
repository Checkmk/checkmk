# EC: syncing slaves don't run actions

key        | value
---------- | ---
date       | 2026-10-22T18:58:39.768785+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

An Event Console replicating the events of a central Event Console ignores
incoming messages while it syncs, leaving them to the central Event Console. Its
periodic housekeeping, however, still handled the synced events: It opened
delayed events and events about missing expected messages, and it deleted
expired events and events created during a downtime of their host. Opening an
event executed the actions of its rule, e.g. sending a notification or running a
script, so such actions could run twice, once on each Event Console. The
history of the replicating Event Console recorded these changes, too, although
its next sync replaced them with the events of the central Event Console.

A syncing Event Console now leaves the housekeeping of the events to the central
Event Console. Once it has taken over, it does the housekeeping itself again,
starting with the events it synced last. It still cleans up its own history,
though.
