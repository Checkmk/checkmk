# EC: failed reloads keep the old config

key        | value
---------- | ---

version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

If the Event Console couldn't set up the history for a new configuration when
reloading it, e.g. when switching the history to MongoDB without MongoDB being
set up, it nevertheless closed its previous history and applied the log levels
of the new configuration. With its history kept in SQLite, the default,
recording the history of its events then failed with errors in
`var/log/mkeventd.log`, and so did every further reload, until the Event Console
was restarted. The Event Console now keeps using its previous history and log
levels in that case.

Similarly, if the Event Console couldn't set up the processing of incoming
messages for its new configuration, e.g. because of SNMP credentials edited by
hand with an unknown protocol, it processed them with the settings of the new
configuration, but the rules of the previous one, and its history failed as
described above. The Event Console now keeps using its previous configuration in
that case, too.
