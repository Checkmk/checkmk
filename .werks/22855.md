# EC: omd reload survives broken configs

version    | 3.0.0b1
class      | fix
edition    | community

compatible | yes

Reloading the Event Console with `omd reload mkeventd` failed badly if its
configuration couldn't be loaded, e.g. because of a syntax error in a
configuration file edited by hand: The Event Console created a crash report and
stopped its periodic tasks like housekeeping, saving its state and replication,
although it kept processing incoming messages. It also removed its PID file, so
`omd status` reported it as not running, and `omd stop` didn't stop it anymore.

Like when reloading after activating changes, the Event Console now logs the
error and keeps running with its previous configuration.

Furthermore, a request to stop or to reload the Event Console which arrived
while it reloaded its configuration, e.g. `omd reload mkeventd` while activating
changes, interrupted that reload, possibly leaving the new configuration only
partially in effect, or the request got lost. The Event Console now completes
the reload first and handles such a request right afterwards.
