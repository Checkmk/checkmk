# EC: limits don't fake missing messages

key        | value
---------- | ---
date       | 2026-10-23T10:07:14.514053+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

A rule with _Expect regular messages_ counts the expected messages in an event
of its own. The event limit of the rule, however, also counted the events about
missing expected messages, which don't respect the event limits themselves. Once
these reached the limit, e.g. a _Custom event limit_ of 1 with an event about
missing messages still open, the Event Console dropped the counting event for
the next expected message. At the end of the interval, it then reported the
expected message as missing, executing the actions of the rule again.

The event limits no longer drop the event counting the expected messages, but it
still counts towards them, and they act on it like on any other event. As there
is at most one such event per rule, it can't flood the Event Console.

Likewise, the event limits now act on the events about missing expected
messages, e.g. by creating an overflow event when such an event reaches a limit,
but they still don't drop them.
