# EC: messages can't stop the housekeeping

key        | value
---------- | ---
date       | 2026-10-23T19:57:07.712218+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

Syslog messages sent to the Event Console can carry structured data of Checkmk,
e.g. `[Checkmk@18662 sl="10" ipaddress="192.0.2.1"]`, which Checkmk itself uses
to pass on the host name, the application, the service level and the IP address
of a message. The Event Console, however, took over any parameter of it as a
field of the event, e.g. its lifetime, its phase or its ID. A single message
setting such a field to an unexpected value could stop the housekeeping of the
Event Console: With e.g. `live_until="tomorrow"`, every housekeeping run failed
with an error in `var/log/mkeventd.log` until the event was archived, even after
a restart. Meanwhile, e.g. delayed events didn't open, and the Event Console
didn't notice missing expected messages.

The Event Console now only takes over the parameters which Checkmk itself sends:
`host`, `application`, `pid`, `msg_id`, `ipaddress` and `sl`. It ignores any
other parameter.
