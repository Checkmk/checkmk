# EC: limits don't act for dropped events

key        | value
---------- | ---
date       | 2026-10-23T14:03:07.130357+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

When a message reached an event limit of the Event Console, but a further limit
dropped it, e.g. the limit of its host, the first limit nevertheless acted on
it: With _Stop creating new events, create overflow event_, it created an
overflow event and notified, if configured, although the event was never
opened. With _Delete oldest event, create new event_, it deleted the oldest
event to make room for an event which was dropped anyway.

Now the limits act only on events which no limit drops.
