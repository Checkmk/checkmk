# EC: stopping or reloading isn't ignored

---------- | ---
date       | 2026-10-23T17:17:01.135412+00:00
version    | 3.0.0b1
class      | fix
edition    | community

compatible | yes

While the Event Console executed the script or sent the email of an action, e.g.
for a delayed event or a missing expected message, while it asked the monitoring
core whether a host is in a downtime, or while it compiled the rules synced from
a central Event Console, it ignored requests to stop or to reload: It logged
them as an error of what it did at that moment. Stopping it with `omd stop` then
took a minute until it was killed, without saving its state, and reloading it
with `omd reload mkeventd` had no effect.

Likewise, an Event Console replicating the events of a central Event Console
ignored these requests while it waited for an answer of the central Event
Console, e.g. because that one was unreachable. It even considered the central
Event Console unreachable then, possibly taking over.

The Event Console now handles these requests in all these cases.
