# EC: name uploaded MIBs by their module

When uploading a MIB file, the Event Console named the MIB after the file in
upper case, e.g. IANA-IFTYPE for a file iana-iftype.mib, although the file
defined IANAifType-MIB. If the MIB defined in such a file failed to compile, the
upload listed this only as an error of another MIB, reported the MIB as
uploaded, and stored the file among the custom MIBs.

An uploaded MIB is named like in its definition now, so such a MIB is refused,
and the message about an uploaded MIB shows its actual name.

Deleting a custom MIB could leave its compiled module behind, so traps were
still translated with it, e.g. if an indented comment mentioning an OBJECT
IDENTIFIER preceded its definition, or delete the compiled module of another MIB
named like its file. The MIB list names a MIB like in its definition now, too,
and also shows the organization of such a MIB.
