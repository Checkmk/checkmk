# mkevent: report undeliverable messages

key        | value
---------- | ---
date       | 2026-11-02T07:47:48.584645+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | no

mkevent ignored most errors when forwarding notifications to the Event Console
and could wait forever for a crashed or stuck one. Now it reports errors and
gives up after 5 seconds, unless it has begun to write a long notification, so
that the notification spooler retries it. With synchronous delivery, it's lost.
Plain messages, e.g. from scripts, give up, too, if nobody reads the event pipe
within 5 seconds, and mkevent exits with 2 for errors a retry can't fix.

For a remote Event Console, mkevent now accepts only IPv4 addresses like
192.0.2.1, as the GUI does. Check the remote hosts in your settings for
forwarding notifications to the Event Console.
