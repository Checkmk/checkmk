# Events without actions on history errors

key        | value
---------- | ---
date       | 2026-11-02T19:36:37.720726+00:00
version    | 3.0.0b1
class      | fix
edition    | community
component  | ec
level      | 1
compatible | yes

When the Event Console couldn't add an entry to its history, e.g. on a full
disk, it stopped processing the event before the actions of its rule and
restarted its event server. A removed event also kept counting for the event
limits.

Now it processes the event as usual and logs such errors in
`var/log/mkeventd.log`, but without flooding it: each kind of error once, then
at most once a minute how many entries are missing.
