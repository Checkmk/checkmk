# Proxmox VE: don't crash on an LRM node without timestamp

key        | value
---------- | ---
date       | 2026-11-03T07:31:29.689468+00:00
version    | 2.5.0p20
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

If Proxmox VE could not read the local resource manager (LRM) status of
a cluster node, for example because the node was down, parsing of the
section `proxmox_ve_ha_manager_status` failed with a `ValidationError`
for `LrmNode`, so the _Proxmox VE HA Manager Watcher_ services crashed.

Checkmk no longer requires a timestamp for such a node. The
_Proxmox VE HA Manager Watcher_ service of that node goes to `CRIT` and shows
its status, for example `UNABLE TO READ LRM STATUS`.

A node status without a date, such as `pve-1 (idle)` or
`pve-1 (active)`, was shown with a trailing parenthesis and therefore
reported as `CRIT`. Such a status is now read correctly, so the service
goes to `OK` for `idle` and `active` and to `WARN` for `maintenance`.
