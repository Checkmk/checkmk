# Bazel cache: no crash on GitHub rate limit

key        | value
---------- | ---
date       | 2026-11-04T08:15:29.243503+00:00
version    | 2.5.0p19
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

The Bazel remote cache special agent looks up the bazel-remote release
tags on GitHub to report available updates. When GitHub answered this
request with an HTTP error, for example "403 Client Error: rate limit
exceeded", the agent crashed and created a crash report, and the cache
metrics were not reported.

The agent now skips the version information in this case, as it
already did when GitHub was not reachable at all. All other data is
reported as usual.
