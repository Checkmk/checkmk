# Remote automations: no error on non-ASCII data

key        | value
---------- | ---
date       | 2026-11-11T09:40:01.505768+00:00
version    | 2.5.0p20
class      | fix
edition    | community
component  | wato
level      | 1
compatible | yes

Actions that run a Checkmk automation on a remote site in the background
(for example the service discovery of a remote host) failed with
"Got invalid data: Internal automation error: The given text must only
contain ASCII characters" when the request contained non-ASCII text,
e.g. a label, alias or host attribute with umlauts.

The remote site now accepts such requests. Update the remote sites to get
the fix.
