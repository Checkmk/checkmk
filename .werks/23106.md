# hr_cpu: Treat processor load outside 0..100 as invalid

key        | value
---------- | ---
date       | 2026-11-10T14:02:58.859641+00:00
version    | 2.5.0p19
class      | fix
edition    | community
component  | checks
level      | 1
compatible | yes

Previously, the _CPU utilization_ service based on the HOST-RESOURCES-MIB
(check plugin `hr_cpu`) accepted any integer a device reported as
`hrProcessorLoad`, although the MIB defines it as a percentage from 0 to 100.
Some devices, observed with the Windows SNMP service on physical servers,
intermittently report values such as 45326 or -993 for every core. The
service then showed totals of several thousand percent or negative
percentages and stored them in the metrics, which distorted the graphs.

The service now treats a per-core value outside 0..100 like an unparsable
one: it goes `UNKNOWN` with the message _Implausible processor load of core
N: got X (expected 0..100)_ and leaves that core out of the total. If no
core delivers a valid value, no total and no metric are produced for that
check cycle.
