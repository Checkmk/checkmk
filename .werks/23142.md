# REST API: reject rule values of the wrong type instead of crashing

key        | value
---------- | ---
date       | 2026-11-17T07:32:25.037470+00:00
version    | 2.5.0p22
class      | fix
edition    | community
component  | rest-api
level      | 1
compatible | yes

Creating or updating a rule via the REST API crashed with
`AttributeError: 'list' object has no attribute 'split'` when the rule
value had a different type than the rule set expects, for example a list
for *Notified events for hosts*, which expects a string such as `"d,r"`.

The REST API now rejects such a value with a 400 error that names the
problem.

This completes werk #23097, which already handled other value shapes the
rule set cannot read.
