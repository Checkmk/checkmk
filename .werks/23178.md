# Time periods: don't crash when saving a clone under an existing ID

key        | value
---------- | ---
date       | 2026-11-17T09:45:34.145368+00:00
version    | 2.4.0p43
class      | fix
edition    | cre
component  | wato
level      | 1
compatible | yes

Saving a cloned time period without changing the prefilled internal ID
crashed with `TimePeriodAlreadyExistsError`, because the duplicate ID was
not checked when cloning.

The form now shows "This name is already being used by another time
period." instead.
